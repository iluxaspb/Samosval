# Steel live-view для OpenCode — тестовая надстройка 0.1

**Не опубликовано на Synology и не готово к рабочему включению без оставшихся проверок.**
Оригинальные контейнеры, файлы OpenCode и настройки Synology не изменены.

## Исследование

- Проверена установленная версия OpenCode 2.2.5. Документация GUI-плагинов:
  https://opencode.ai/v2/docs/build/plugins/gui — описывает загрузку сторонних
  GUI-плагинов из Desktop. В установленном web bundle есть GUI SDK и registry,
  но работоспособность загрузки стороннего плагина именно в standalone web
  **не доказана**. Выбран обратимый sidecar вместо форка или правки бинарника.
- Steel `/v1/sessions` и `/v1/sessions/{id}/live-details` доступны внутри сети.
  Возвращаемые viewer URLs содержат localhost и не подходят для телефона.
  `/v1/sessions/debug` отдаёт плеер с `/v1/sessions/cast`; этот путь в данной
  установке закрывает WebSocket. Вариант с ID сессии отвечает 101, но фактически
  передаёт CDP (`Browser.getVersion`), а не готовые кадры плеера.
- Использован штатный **CDP Page.startScreencast** существующего Steel Chromium:
  это push-поток кадров и acknowledgements, не периодические screenshot-запросы.
  CDP target ID страницы MCP сопоставлен с live-details Steel.

## Устройство

`server.mjs` проксирует существующий HTTP-интерфейс OpenCode и добавляет один
внешний JS-файл в HTML. Бинарник и assets OpenCode остаются оригинальными.
`panel.js` рисует поток, добавляет кнопку «Браузер», режимы просмотра/управления,
полноэкранную панель, масштаб 200%/400% и поле ввода текста для экранной клавиатуры.
Desktop-страница 1920 px в режиме «Вписать» на телефоне мелкая; zoom не меняет
viewport браузера MCP. В режиме просмотра увеличенное изображение прокручивается
касанием; в ручном режиме касания направляются удалённой странице. Удобство на S25
не следует считать доказанным этим прототипом.

Сервер не проксирует Steel API или произвольный CDP наружу. Авторизация HTTP и
WebSocket — серверная Basic Auth с существующим OPENCODE_PASSWORD, обязательный
точный Origin для WS. Пароля/постоянного токена в URL нет. **Внешнее использование
разрешено только через HTTPS**, внутренний HTTP — только в доверенной сети.
Просмотр блокирует входящие события на сервере; manual разрешает ограниченные
мышь/клавиатуру. Доступ к текущей браузерной странице получает любой обладатель
этого пароля: многопользовательская изоляция/ACL чатов пока не реализованы.

Target задан явно и проверяется в активной Steel-сессии при подключении. При
закрытии target сервер отказывает, а не выбирает чужую страницу. При новой
странице/перезапуске Chromium нужно заново сверить MCP target и обновить параметр.
Автоматическая привязка новых targets к чатам пока отсутствует.

### Предпросмотр текущего чата и вход пользователя

Добавлен явный мост `agent-browser.mjs`: агент сообщает путь текущего чата и
командой `show` открывает панель, `login` включает ожидание пользователя.
Пользователь вводит данные непосредственно в браузере и нажимает
«Я вошёл — продолжить». Ручной режим отзывается сервером; команда агента
завершается без передачи введённых данных. В другом чате панель скрывается.
Это кооперативная пауза, **не блокировка прямого MCP/CDP**. Автообнаружение
работы агента и автоматическое подключение глобальных hooks не реализованы.
Подробный протокол и ограничения: [AGENT_INTEGRATION.md](AGENT_INTEGRATION.md).
Состояние handoff хранится только в памяти: restart отменяет ожидание.

Состояние подключения/Steel отображается, закрытие потока показывается.
Автоматического статуса «тест успешно завершён» нет: browser idle не означает
успех теста. Отчёт о тестах формирует отдельный test runner.

## Проверенный локальный запуск

```sh
npm ci --ignore-scripts
npm test
node --check server.mjs
node --check panel.js
```

Для старта нужны защищённо переданные переменные окружения:

- `OPENCODE_UPSTREAM` — фактический внутренний HTTP URL OpenCode, порт не угадывать;
- `OPENCODE_PASSWORD` — существующий пароль сервера, не сохранять в репозиторий;
- `STEEL_UPSTREAM` — внутренний URL Steel;
- `STEEL_TARGET_ID` — CDP target из реального MCP-вызова `Target.getTargetInfo`;
- `VIEW_ORIGIN` — точный origin тестового интерфейса;
- `PORT`, `BIND_HOST` — по умолчанию `4180`, `127.0.0.1`.

```sh
node server.mjs
```

Тест `browser-test.mjs` подключается к **существующему** Steel, использует только
пустую pinned-страницу и временный дополнительный context для просмотра UI.
Он не запускает второй Chromium. Тестовая страница — существующий изолированный
`tests/paper-viewer/benchmark.html`, а не рабочий index.html/index-test.html.
Все запросы target перехватываются: разрешены только два локальных fixture-файла.
После теста страница возвращается в about:blank. Запускать только при отсутствии
другой автоматизации/ручной работы в этом Chromium.

```sh
TEST_VIEW_ORIGIN=http://internal-test-host:4180 node browser-test.mjs
```

Для варианта с реальным MCP установить `MCP_DRIVEN=1`, дождаться сообщения READY
и через MCP нажать `#control-test` только на подготовленной fixture-странице.
Артефакты: `test-results/report.json`, `test-results/mobile.png` (gitignored).

## Synology — подготовлено, но НЕ выполнено

`Dockerfile` и `compose.test.yml` описывают отдельный opt-in сервис; existing
network `opencode2-lab_default`, bind порта **только 127.0.0.1:4180**, restart policy,
read-only filesystem, без Docker socket и прав root. Они не меняют существующий
compose. Сборка Docker здесь не проверена: нет CLI/socket и /volume2.

После согласования разместить файлы отдельно в `/volume2/docker/opencode2-lab`,
проверить реальные mounts/версию/внутренний порт контейнера, передать секреты
вне Git и поднять только новый compose-проект. Для локальной проверки возможен
SSH tunnel; существующий 4097 не перенастраивать.

**До внешнего теста нужны отдельное разрешение и тестовый reverse proxy маршрут.**
Проверить на нём HTTPS, `Upgrade: websocket`, `Connection: upgrade`, Authorization,
Origin, длительность соединения и отсутствие буферизации. Не отключать защиту
Origin ради устранения 403. Не открывать 3000/8931/CDP наружу. Внешний HTTPS GET
на 4097 вернул 200, но это **не проверка WebSocket через Synology**.

Сохранение файлов и restart policy подготовлены. Реальный recreate/restart
контейнеров и сохранность параметров после него не проверялись.

## Фактический результат 2026-10-31

- 4 теста защиты/WebSocket proxy/handoff прошли; npm audit: 0 vulnerabilities.
- 12 проверок браузерного MCP-прогона прошли, включая настоящий клик через MCP,
  увеличение счётчика кадров, manual touch и Unicode-ввод в тот же target,
  401/403 и поддельные WS-команды в режиме просмотра, разворачивание/сворачивание.
- Проверен Chromium с mobile/touch viewport **360×780**, не физический S25.
- `fixtureWrites` пуст; PostgreSQL/Firebase/NAS не использовались.
- Один промежуточный дополнительный прогон завершился timeout на ожидании кадра;
  исправлен test barrier и cleanup, последующий полный MCP-прогон прошёл.
- После добавления zoom/touch-pan отдельный браузерный прогон: 13 проверок прошли.
- WebSocket OpenCode проксируется только в фиксированный upstream после проверки
  credentials и Origin; echo-тест подтвердил текст/бинарные сообщения. Реальный
  PTY API/WebSocket также проверен, полный чат и UI терминала ещё не проверены.

Дополнительные opt-in проверки (создают и удаляют только свои временные ресурсы):

```sh
OPENCODE_UPSTREAM=http://actual-internal-opencode:port node opencode-integration.mjs
node target-close-test.mjs
```

Первый тест проверяет настоящий OpenCode PTY, второй — закрытие отдельной
пустой страницы в существующем Steel, не страницы MCP. Не запускать параллельно
с пользовательской работой. Проверять upstream по API: доступность HTML не
доказывает, что выбранный сервер принимает ту же авторизацию API.

Остаются: физический Android/Samsung Internet/Chrome, IME и реальная авторизация
на разрешённом сайте, landscape/вращение/жесты прокрутки, внешний Synology WSS,
нагрузка/длительные сессии/reconnect, автоматическая привязка targets и состояние
завершения теста, web-plugin capability spike. Перед эксплуатацией — отдельный
review безопасности и защита от одновременного ручного управления/автоматизации
(сейчас только предупреждение и явное переключение, не блокировка MCP).
