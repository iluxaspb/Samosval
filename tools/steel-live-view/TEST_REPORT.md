# Фактическая проверка — 2026-10-31

Статус: тестовый прототип проверен в доступном окружении; на Synology не установлен.

## Итоговая интеграционная проверка

- `opencode-integration.mjs`: настоящий API OpenCode на внутреннем :4096,
  создание временного PTY, короткоживущий одноразовый ticket и WebSocket
  ввод/вывод через sidecar прошли. Созданный тестом PTY удалён и отсутствие
  его ID в списке подтверждено. Чужие терминалы не изменялись.
- Исправлена передача HTTP Origin: только точный внешний Origin разрешён,
  upstream получает собственный Origin. Unit proxy-тест проверяет также 403
  для чужого HTTP Origin. Для выдачи PTY ticket нужен штатный x-opencode-ticket: 1.
- Managed service :49374 не принимал Basic Auth для API (401), тогда как
  :4096 принимал. Нельзя выбирать upstream лишь по доступности HTML.
- `target-close-test.mjs`: закрыта только созданная тестом пустая страница
  отдельного context в существующем Steel. Получены targetClosed и закрытие
  WS; последующий status вернул 503, без переключения на другую страницу.
- Последний полный мобильный прогон: 16/16, затем временный proxy остановился.
  Исправлена очистка upstream HTTP-потоков при закрытии клиентского соединения.
  Предыдущий прогон выполнил 16 проверок, но завис при shutdown; его не считаем
  успешным завершением. Отдельный прогон отказался заменять непустую страницу.
- Полноценный чат с модельным ответом и UI терминала по-прежнему не проверены;
  API/PTY roundtrip не заменяет эти сценарии.

- `npm test`: 4/4 теста, включая state machine передачи управления.
- Полный mobile/touch прогон `browser-test.mjs`: 16 проверок прошли.
  Дополнительно проверены автооткрытие панели по `show`, переход `login` →
  ручное управление → «Я вошёл — продолжить», отзыв manual и очистка поля,
  скрытие предпросмотра при переходе на другой чат.
- На последней версии отдельный процесс `agent-browser.mjs login` оставался
  активным до явного resume; после resume завершился с кодом 0. Проверялось
  только состояние протокола, без передачи учётных данных.
- URL чата в тесте синтетический через history.replaceState: реальный чат,
  оплачиваемый запрос модели и пользовательские сессии не изменялись.
- Два промежуточных прогона остановились по тайм-ауту на manual acknowledgement:
  исправлена гонка готовности WS и события закрытия предыдущего соединения.
  Следующий полный прогон прошёл.
- Протокол агента описан в AGENT_INTEGRATION.md; глобальные hooks/правила
  не устанавливались. Это кооперативная пауза, не техническая блокировка MCP.

## Выполнено

- `npm test`: 3/3 теста прошли: защита и отдельный WebSocket echo-upstream.
  Подтверждена передача текста/бинарных сообщений и query string только в
  фиксированный upstream OpenCode с авторизацией; Steel/CDP не проксируются наружу.
- `npm audit`: 0 известных уязвимостей.
- Синтаксис server.mjs, panel.js и browser-test.mjs проверен Node.js.
- Последний browser-test.mjs: 13 проверок прошли, mobile/touch Chromium 360×780.
  HTTP без авторизации — 401; WS без credentials/с чужим Origin — 403;
  поддельный управляющий WS-пакет в режиме просмотра не изменил страницу.
  Панель встроена поверх оригинального OpenCode, получены screencast-кадры;
  проверены fullscreen/collapse, zoom 400%/touch-pan, manual click, Unicode-ввод,
  обновление кадров при автоматизации. fixtureWrites остался пустым.
- Отдельный полный прогон с MCP_DRIVEN=1: 12 проверок прошли до добавления zoom.
  Настоящий Playwright MCP нажал #control-test, счётчик изменился на 2;
  runner подтвердил увеличение числа полученных живых кадров после этого действия.
- После тестов target возвращён в about:blank, временный viewer context закрыт.

Тест использовал существующий изолированный benchmark «Учёта самосвалов» и
добавленные только в DOM контрольные кнопку/поле. Это не прогон работающей
index-test.html и не авторизация на настоящем сайте. Сеть fixture ограничена
двумя локальными файлами через route.fulfill; реальные backend не использовались.

## Непроверенное и ограничения

- Физический Samsung S25, Samsung Internet, реальная Android IME и вход на сайт.
- Внешний Synology WebSocket proxy: GET 200 не доказывает WSS Upgrade.
- Docker build/compose, mounts, restart/recreate: нет Docker CLI/socket и /volume2.
- Загрузка стороннего GUI-плагина standalone web 2.2.5: не подтверждена.
  Sidecar выбран как обратимая надстройка, не как доказательство отсутствия API.
- Привязка нового target после перезапуска требует явного обновления параметра.
- Нет блокировки конкурирующих MCP/manual действий и ACL по чатам.
- Нет автоматического статуса успешного завершения теста; отображаются только
  состояние Steel при подключении и закрытие потока.
- Полный чат и UI терминала не проверены. Настоящий PTY API/WebSocket проверен
  отдельно, как описано выше; это не проверка внешнего Synology WSS.

Первый вариант штатного Steel player не передавал кадры. Прототип переведён на
Page.startScreencast существующего Steel Chromium (push, не screenshot polling).
Один промежуточный security-прогон завис на ожидании кадра: ожидание заменено
на WS acknowledgement barrier, cleanup исправлен, повторные прогоны прошли.
