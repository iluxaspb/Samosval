# Винкор Android принтер

Отдельное PWA для заполнения готовых бумажных бланков на линии. Версия 0.1.4 — предварительная.

## Реализовано

- Мобильный интерфейс, светлая/тёмная тема, необязательный виброотклик (если поддержан браузером).
- База самосвалов: госномер, водитель, марка, перевозчик, объём, произвольные пары ключ=значение.
- Выбор машин галочками. Четыре машины = четыре страницы; копии сохраняют один номер документа на машину.
- Общие данные задания, сегодняшняя дата при запуске и создании нового задания, ручное изменение даты.
- ТТН АБЗ: чистое изображение извлечено из предоставленного CFP; исходные позиции полей приблизительные, не перенесены из двоичного формата CFP.
- Редактор: перетаскивание, масштабирование двумя указателями, панорамирование, координаты в мм, стрелки, шаг подгонки, ширина, размер шрифта, жирность, выравнивание, закрепление, копирование/удаление, отмена последних 40 изменений текущего шаблона.
- Общий сдвиг печати в шаблоне; фон никогда не печатается.
- Несколько шаблонов; загрузка JPEG/PNG/WebP, размер листа; произвольные текстовые поля и связи с базой.
- История последних 200 подготовленных заданий с неизменяемыми снимками машин, шаблона и даты.
- IndexedDB, экспорт/восстановление всей базы. Восстановление заменяет данные после подтверждения.
- PWA manifest и service worker с кэшированием основных файлов. Нужен HTTPS (GitHub Pages).
- Печать через браузер / сохранение PDF при наличии этой возможности в ОС.
- Экспериментальный WebUSB: запрос устройства, диагностика интерфейсов, стандартный USB printer class 7/bulk OUT, 24-игольчатый растр 180 dpi. Предварительная подготовка и отправка выбранного пакета; сохранение выбора USB-принтера на этом устройстве.

## Что не подтверждено

**Пользователь подтвердил физическую печать и правильное расположение полей в версии 0.1.0. Оптимизированная передача версии 0.1.1 ещё требует проверки на физическом принтере.** Печать всего пакета после отключения телефона пока не подтверждена. Конкретная ревизия может предоставлять vendor-specific либо USB-serial интерфейс: эта версия только покажет диагностику и не будет отправлять неизвестные команды. Windows DLL не используются.

Код формирования растра основан на командах из предоставленного HPR4915.GPD, включая ESC * 39. Не реализованы специализированный language monitor и надёжный двусторонний опрос состояния бумаги. «Отправлено» означает только передачу байтов, а не подтверждение отпечатка. Не повторять автоматически при ошибке; проверить частичную печать, бумагу и состояние принтера.

Системная печать на Android сама по себе не добавляет драйвер Wincor. Она требует установленной совместимой службы или может использоваться для PDF. Размер бумаги и масштаб в системном диалоге могут влиять на положение: 100%, без полей/колонтитулов. Поля шаблона требуют физической калибровки.

Масштаб двумя пальцами и виброотклик реализованы, но требуют проверки на реальном Samsung. Офлайн-установка требует проверки на опубликованном HTTPS URL. Сетевая печать через Orange Pi, синхронизация между операторами, APK и интеграция с «Учётом самосвалов» не входят в 0.1.0.

## Размещение в Samosval

Приложение находится в отдельной папке `wincor-android-printer/` репозитория `iluxaspb/Samosval`, ветка разработки — `feature/wincor-android-printer`.

Файлы в этой папке самостоятельны: основной HTML Samosval, его Firebase, API, хранилища и сборка не используются. Внешних библиотек и компиляции нет. Самостоятельный workflow Pages намеренно не добавлен: публикация только этой папки как всего сайта могла бы заменить сайт Samosval.

Локально из этой папки: `python3 -m http.server 8080`, затем открыть `http://localhost:8080/`.

Тесты из этой папки: `npm test` (Node.js 22+).

Ветка разработки сама по себе не получает отдельный адрес GitHub Pages. Для публикации внутри существующего сайта потребуется отдельно согласованное добавление папки в текущий Pages-источник или изменение общего процесса публикации с сохранением всех файлов Samosval. Проверенная текущая настройка Pages: Deploy from branch `root`, папка `/(root)`. Ветка `feature/wincor-android-printer` сама не опубликована. Следующий шаг — отдельно согласованный перенос только этой папки в `root`, без замены остальных файлов. Настройки Pages и рабочая ветка этим изменением не меняются.

## Изоляция PWA

- Manifest `id`, `start_url` и `scope` равны `./` и разрешаются относительно собственной папки.
- Service worker регистрируется с явным `scope: './'`, обрабатывает только GET внутри своей папки и своего origin.
- Кэш имеет префикс `wincor-android-printer:<путь-папки>:`. Очистка затрагивает лишь старые версии этого префикса; чтение ведётся через свой cache, а не глобальный `caches.match`.
- IndexedDB — `wincor-android-printer-db-v1`. Нет обращения к базам Samosval или общим ключам localStorage.
- Приложение не удаляет и не отменяет регистрацию чужих service worker.
- Это организационная изоляция, не отдельная граница безопасности origin: любой JS на том же домене технически имеет общие права на хранилища. Также родительский SW Samosval может затронуть первый заход в подпапку до регистрации её собственного SW. При проверке снимка `ad287469b2ba474fd1146ac36979a919a2e53156` родительским агентом установлено: корневой `sw.js` использует точный список разрешённых fetch и собственный префикс очистки `samosval-shell-`; `sw-test.js` использует отдельный префикс. Перед публикацией после изменений Samosval эту проверку следует повторить.

При обновлениях изменять версию CACHE в `sw.js`. Обновление ожидает закрытия старых вкладок; данные IndexedDB не удаляются. Не менять origin/path без переноса базы через экспорт.

## Данные

На сервер не передаются база машин, заполненные поля и задания. Каждый браузер имеет свою базу; операторы могут обмениваться резервными копиями вручную. Очистка данных сайта удаляет локальную базу. Первоначальная поставка содержит пустую базу и только чистый скан ТТН. Исходный CFP с заполненными сведениями и Windows DLL не публикуются.

## Проверено в разработке 0.1.0

10 автоматических тестов: изоляция manifest, регистрации SW, очистки и чтения кэшей, фильтрации запросов; 4 машины → 4 страницы, копии/нумерация, неизменность снимков, ошибочный выбор, дата/пользовательские поля, валидация копии, упаковка растровых битов. В браузере проверены создание машины, выбор, предпросмотр, поле даты, сдвиг 0.5 мм и отмена, увеличение, адаптивный экран 390 px. Новая оптимизированная передача физически не проверена.


## Изменения 0.1.1

- Растровые полосы без чернил больше не передаются как графика. Пустые колонки слева и между заполненными участками заменяются командами горизонтального позиционирования ESC $, справа обрезаются. Исходная подача бумаги сохранена; тесты сравнивают координаты всех печатаемых точек со старым потоком.
- Пакет выбранных бланков подготавливается заранее; интерфейс показывает фактический размер и отправляет весь пакет одной кнопкой.
- Кнопка «Сохранить принтер» запоминает идентификаторы. При повторном подключении используется однозначно совпавшее разрешённое устройство. При сбросе разрешения или неоднозначном выборе снова показывается системный список.
- Через 15 секунд показывается ожидание приёма данных вместо ложного отказа. Через 2 минуты незавершённая передача закрывает USB, блокируя повтор до завершения закрытия. Автоповтора нет.
- Предусмотрены явное обновление PWA и сохранение базы; новая версия кэша 0.1.1.

### Проверки 0.1.1

Юнит-тесты: `npm test`. Браузерный сценарий: `node tests/usb.browser.mjs` (требует установленного Playwright и Chromium, например `npm install --no-save playwright`, `npx playwright install chromium`). Он проверяет мобильный экран, размер пакета, сохранённый USB-принтер с эмуляцией устройства и сохранность IndexedDB после обновления SW. Наличие файла теста само по себе не означает успешный прогон. Физический тест с принтером, включая автономную печать после отсоединения телефона, остаётся обязательным.

В CI закреплены Ubuntu 22.04 и Playwright 1.56.1: переход `ubuntu-latest` на Ubuntu 26.04 оказался несовместим с установкой браузера этой версии. Закрепление среды предотвращает повтор такого сбоя.


## Изменения 0.1.2: подключение USB

- «Поиск принтера» находит уже разрешённый подключённый принтер без системного списка. Если разрешения нет, появляется отдельная кнопка «Разрешить доступ к принтеру». Первое разрешение Chrome нельзя пропустить.
- «Выбрать другой принтер» открывает системный выбор непосредственно по нажатию, с фильтром класса принтеров. Отмена сохраняет текущее подключение и запомненный выбор.
- Подходящий bulk OUT канал выбирается автоматически среди всех конфигураций и альтернатив. Если первый канал занят, проверяется следующий без отправки пробных команд.
- Несколько физических принтеров с одинаковыми идентификаторами не объединяются произвольно: приложение просит оставить один или выбрать явно. Список Android/Chrome и его названия приложение не может переписать.
- Состояние подключения показывается понятным текстом, номера интерфейсов скрыты под «Технические сведения». При отключении OTG кнопки обновляются.
- Открытый USB-канал не подтверждает физическую печать: нужен один пробный бланк на реальном Wincor.

## Изменения 0.1.2: поля рейса

Новое поле в редакторе по умолчанию имеет источник «Ввод для рейса». Назови его, расположи на бланке и заполни значение в разделе «Данные рейса и груза». Название служит подписью, на печать попадает введённое значение. Переименование сохраняет черновик; копии полей независимы. Черновики разделены по шаблонам, история хранит значения на момент подготовки. Для неизменной надписи выбери источник «Постоянный текст».

## Изменения 0.1.3

- Подключение распознаёт WN HighPrint 4915/4915xe и сохранённую пару VID/PID. Свежий разрешённый объект из события подключения используется непосредственно, без выбора по номеру или порядку в списке Chrome.
- Ручной поиск проверяет открытие разрешённых Wincor без печатных команд; записи с NotFoundError пропускаются. Отказ разрешения не повторяется. Если доступны несколько устройств, автоматический выбор не делается. Эта проверка не исправляет внутренний список Android/Chrome и ещё требует испытания на устройстве пользователя.
- «Отправить при подключении» вооружает только текущий подготовленный пакет в открытом диалоге. Подключение отправит его один раз. Закрытие диалога отменяет ожидание; после ошибки и переподключения автоповтора нет. После перезапуска приложения ожидание не восстанавливается.
- «Диагностика USB» показывает копируемый журнал последних 120 событий: подключение, этапы открытия, ошибки, смещения и счётчики передачи. Содержимое бланков и серийные номера не записываются. Открытие диагностического диалога отменяет вооружённую отправку.
- В редакторе доступны шрифт и курсив, включая изменение шрифта всех полей текущего шаблона. Эти настройки используются в редакторе, предпросмотре, PDF/системной печати и USB-растре, сохраняются в копии и истории. Конкретный установленный шрифт зависит от устройства; семейства используют безопасные fallback.

Автономная печать после отключения телефона не подтверждена. Приём без бумаги может блокироваться самим принтером даже для небольшого пакета. Все байты переданы по USB — не подтверждение отпечатка или сохранения задания в памяти. Протокольные команды буферизации и аппаратные настройки этим выпуском не меняются.

## 0.1.4

Подключение WN HighPrint 4915xe (USB VID 2727 / PID 17152) проверяется автоматически, пока приложение видно. При возвращении на экран проверка возобновляется. Уже открытый канал не переоткрывается, отказ доступа не повторяется циклически. Если Chrome не предоставляет подключённое устройство, нажми «Разрешить доступ»; приложение не может открыть системный запрос без нажатия.

Режим «Без самосвала» создаёт 1–20 бланков без данных машины, сохраняя остальные поля рейса.

Флажок «Начать без бумаги» — эксперимент: вместо стандартных USB-порций 4096 байт передаются порции 64 байта. Последовательность байтов и команды не меняются. Режим фиксируется в начале передачи. Это НЕ решение ожидания бумаги: принтер может продолжать блокировать передачу до подачи листа; автономная печать после отключения телефона не подтверждена. Повтор автоматически не запускается.

«Диагностика USB» позволяет скопировать или скачать JSON-журнал после результата передачи. Он включает версию приложения, режим, подтверждённые байты, длительность USB-операций, ошибки и итог последней передачи. Содержимое бланков и серийные номера не записываются; локальный ключ позволяет сравнить серийные номера только внутри текущей сессии. Журнал ограничен 4096 событиями; droppedEvents явно показывает число отброшенных событий, итог последней передачи сохраняется отдельно.
