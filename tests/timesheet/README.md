# Табель объекта, тестовая версия 3.2.0

Работает только в `index-test.html` с проектом Firebase **samosval-offline**. Основной `index.html` и рабочий проект **samosval-test** не изменяются. Реальных сотрудников, рейсы и часы при выпуске автоматически не создаём.

## Перед запуском

Сначала применить `firestore-timesheet-test.rules` в **samosval-offline**, затем выпускать `index-test.html`. Версия 3.2.0 добавляет поля экипажа и коллекции `timesheetShifts`/`timesheetSettings`: правила 3.1.2 с `hasOnly` не разрешают эти записи. Публикация файлов в GitHub сама по себе не публикует правила Firebase.

В Firebase Console: проект **samosval-offline** → Firestore Database → Rules. Сохранить копию действующих правил, сверить изменения вне табеля, применить подготовленный файл. Фактические облачные правила из GitHub не читаются. **Не применять к samosval-test.**

Файл правил сохраняет существующие права и UID владельца тестового проекта. Вкладка доступна администратору. Для остальных ролей существующая настройка «Админ → Права» разрешает вкладку «Табель» и действия `timesheet_edit`, `timesheet_manage`, `timesheet_export`. Новые настройки направления материала требуют права справочников; при закрытии смены разовое направление можно выбрать с существующим `close_shift`.

## Поведение

- Справочники: рабочие, ИТР, машинисты/водители со специализацией, техника с явным типом. У своей техники фирма не требуется. Для наёмной включается флажок и обязательная фирма.
- В смену добавляется только техника. У своей фрезы по умолчанию два машиниста, у щётки один тракторист, у поливомойки один водитель. Часы учитываются без фамилий. Третий машинист и дополнительные места доступны в окне экипажа.
- Нажатие на подпись экипажа открывает необязательные фамилии только нужной специализации и индивидуальные часы. Позднее указание фамилии меняет существующее место, не добавляя второе начисление. У наёмной техники нет экипажа и человеко-часов водителей.
- Старые именные строки сохраняются. Если у старой своей техники нет экипажа, штатные места отображаются виртуально; записываются при вводе часов/состава. Старые строки водителей наёмной техники остаются в истории, но исключаются из расчётов и выгрузки.
- Порядок и палитра: поливомойка, щётка, фреза, фронтальный погрузчик, автобус, XCMG, прочая техника; материалы, ИТР, рабочие. При отсутствии явного типа старой техники используется название.
- Стрелки дат, «Вчера», «Сегодня». Начало и конец смены, включая переход через полночь. Длительность используется в быстрых кнопках и поле «Часы всем рабочим»; сама по себе не заполняет фактические часы. «Пустым по … ч» заполняет только незаполненные строки.
- Компактный ввод произвольных часов, быстрые 12/13 и плюс/минус. Общие часы рабочим не меняют ИТР и машинистов. В сводке техники учитываются уникальные самосвалы на линии выбранного объекта и даты, без ГАИ.
- Месячная таблица отдельная для объекта, с цветными парами техника/экипаж. Показываются только смены с записанными часами. В строках экипажа суммарные человеко-часы; часы машины отдельно. Материал сгруппирован по материалу, направлению/поставщику и единице. Поступления в даты без часов остаются в отдельном реестре под таблицей и в CSV материалов.
- Название материала свободное (например, гранулят или диабаз). Направление по умолчанию сохраняется для объекта: конус, завод или другой объект. При закрытии подтверждаются направление и дневная/ночная смена табеля. Объём — сумма фактических рейсов без ГАИ.
- Материал из рейсов вычисляется из закрытого архива, а не дублируется отдельным поступлением. При передаче на другой объект источник видит передачу, получатель поступление. Повторное закрытие использует тот же ID архива; повторно восстановленные смены имеют стабильный идентификатор источника. Изменение рейсов архива изменяет производный объём. Ручные поступления по накладным независимы.
- История до/после, мягкое удаление, авторы изменений; очередь IndexedDB отдельно для проекта, рабочей области и пользователя, явные конфликты версий.

## Данные и совместимость

Коллекции внутри `workspaces/main_workspace`: `timesheetPeople`, `timesheetEquipment`, `timesheetEntries`, `timesheetMaterials`, `timesheetShifts`, `timesheetSettings`, `timesheetChanges`.

Штатное место экипажа имеет стабильный `entityId=tscrew_<equipmentId>_<index>`; необязательный `personId` указывает выбранного сотрудника. Старые именные записи без `personId` читаются по прежнему `entityId`. Часы — целые минуты; незаполнено, ноль, выходной и отсутствие различаются. Состав и время независимы по объекту, дате и дневной/ночной смене.

Операция до 4 строк и снимки до/после записываются одной транзакцией (лимиты обращений Firestore Rules). Большие группы разбиваются на операции; весь набор сначала атомарно сохраняется локально. Поэтому большой набор синхронизируется частями, с видимым счётчиком очереди. `revision` защищает от перезаписи; `timesheetChanges` — неизменяемая история и квитанция повторной отправки.

Автоматический материал хранит направление в `archive.materialRoute`, дату/смену в `date`/`timesheetShift`, источник в `materialSourceId`. Старые архивы без направления автоматически не начисляют материал: у них неизвестно назначение. Закрытие также сохраняет обычные снимки самосвалов для исторического подсчёта, включая смены без загруженных рейсов.

CSV — выгрузка для Excel и переноса в 1С, не готовый импорт в конкретный документ 1С. Экспорт ждёт подтверждения сервером и разбора очереди месяца; для материалов также ждёт архив. Полноценный складской остаток, расход из конуса и распределение одной смены между несколькими получателями пока не реализованы. Холодное открытие без интернета зависит от кэширования основной программы; уже открытый табель сохраняет правки локально.

## Проверки

Из корня репозитория, с зависимостями из `tests/timesheet/package.json`:

```sh
node tests/timesheet/build.cjs
node tests/timesheet/core.cjs
node tests/timesheet/material-core.cjs
node tests/timesheet/close-shift.cjs
NODE_PATH=tests/timesheet/node_modules node tests/timesheet/ui.cjs
NODE_PATH=tests/timesheet/node_modules node tests/timesheet/compact-ui.cjs
NODE_PATH=tests/timesheet/node_modules node tests/timesheet/crew-ui.cjs
NODE_PATH=tests/timesheet/node_modules node tests/timesheet/revision-ui.cjs
NODE_PATH=tests/timesheet/node_modules FIRESTORE_EMULATOR_JAR=/path/to/firestore-emulator.jar node tests/timesheet/emulator.cjs
```

Эмулятор `demo-timesheet` на `127.0.0.1:8091`; автоматические тесты не используют облачные базы. Проверяются новые поля и правила, права ролей, экипажи, конфликты и офлайн, даты/длительность, таблица, направления материала, исключение ГАИ, отмена и повторное закрытие после сбоя. `fixture.js` — только локальные тестовые данные, в приложение не встроен.

Для временного отката восстановить только прежний `index-test.html`. Данные, правила 3.2.0 и очереди не удалять. Старый интерфейс не умеет корректно управлять штатными местами, поэтому до повторного включения 3.2.0 не редактировать новый состав через старую версию.
