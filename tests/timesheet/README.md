# Табель объекта, тестовая версия 3.1.1

Работает только в index-test.html с проектом Firebase samosval-offline. Основной index.html и рабочий проект samosval-test не изменяются. Реальных сотрудников и часы при выпуске автоматически не создаём.

## Возможности

- Общие справочники сотрудников и техники, своя/привлечённая техника, экипажи.
- Люди, техника и материалы по объекту, дате начала и дневной/ночной смене.
- Компактные строки смены: прямой ввод часов, быстрые 12/13 и плюс/минус; отдельные итоги рабочих, ИТР, машинистов и техники.
- Кнопка «Часы всем рабочим» меняет только рабочих выбранной смены. Обычный экипаж техники выбирается только из машинистов/водителей.
- Часы группы, перенос состава без часов, месячная таблица, CSV для Excel.
- История до/после, мягкое удаление, именованные авторы изменений.
- Очередь IndexedDB отдельно для проекта, рабочей области и пользователя; подтверждение сервером; явный разбор конфликтов.
- У одного сотрудника одна строка на объект/дату/смену, в ней одна привязка к технике. Работа на нескольких машинах внутри смены пока не разбивается на интервалы.
- Формат конкретного документа 1С и движение гранулята/конусов ещё не реализованы.

## Включение для операторов

В Firebase Console проекта **samosval-offline**, Firestore → Rules применить firestore-timesheet-test.rules. Этот файл включает текущую схему v3 и правила табеля, с UID владельца тестового проекта. Не публиковать в рабочий samosval-test. Фактические текущие правила Firebase не читаются через GitHub; перед заменой сохранить их копию и сверить, что нет более новых изменений.

Администратору вкладка видна автоматически. Для остальных ролей в Админ → Права включить вкладку «Табель» и нужные действия: часы и материалы, справочники и экипажи, выгрузка CSV. Существующие права автоматически не расширяются. До применения новых правил старая общая политика может разрешать новые коллекции только администратору.

## Хранение

Новые коллекции внутри workspaces/main_workspace: timesheetPeople, timesheetEquipment, timesheetEntries, timesheetMaterials, timesheetChanges. Идентификатор строки часов однозначен для вида, объекта, даты, смены и сотрудника/машины. Часы хранятся целыми минутами. Нулевая запись, отсутствие, выходной и незаполненная строка различаются.

Каждая операция (до 4 строк из-за лимита обращений в Firestore Rules) и её снимки до/после записываются одной транзакцией. Большой состав/группа разбивается на такие операции; весь набор сначала атомарно сохраняется в локальную очередь. Синхронизация большого набора может быть частичной, что видно по счётчику оставшихся операций. Обновления проверяют ожидаемую revision. timesheetChanges служит неизменяемой историей и квитанцией для повторной отправки. Синхронизация запускается только при активной учётной записи с доступом к вкладке.

CSV доступен после подтверждения сервером и разбора всей очереди выбранного месяца. Это обычная выгрузка данных, не готовый импорт в 1С. Доступность при холодном открытии без интернета зависит от существующего кэширования основной программы; модуль обеспечивает очередь изменений уже открытого приложения.

## Сборка и проверки

Из корня репозитория:

```sh
node tests/timesheet/build.cjs
node tests/timesheet/core.cjs
node tests/timesheet/ui.cjs
node tests/timesheet/compact-ui.cjs
FIRESTORE_EMULATOR_JAR=/path/to/firestore-emulator.jar node tests/timesheet/emulator.cjs
```

Зависимости перечислены в package.json этого каталога. Установить там npm install, затем запускать с NODE_PATH=tests/timesheet/node_modules. Эмулятор использует demo-timesheet на 127.0.0.1:8091. Рабочая и тестовая облачные базы не используются для автоматических тестов. fixture.js содержит вымышленные записи для локальной проверки интерфейса; он не встроен в приложение.

Для отката восстановить только index-test.html из родительского коммита. Новые данные и очереди на устройствах не удалять.
