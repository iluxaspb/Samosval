# Срочный откат 4.0 → 3.4

25 октября 2026 владелец сообщил о неработающих регистрации и закрытии смены после 4.0 и потребовал немедленно восстановить прежний один HTML-файл.

`index.html` восстановлен из `releases/4.0/index-before-release.html.txt`, снимка рабочего приложения до выпуска 4.0. Исполняемый код не менялся; только цвет номера 3.4 изменён на зелёный по ранее установленному правилу. Манифест возвращён к сохранённому состоянию.

`recovery-3.4.html` содержит тот же HTML и служит прямым входом в обход кеша неисправной версии 4.0. Первый запуск требует интернета. Firebase-проект, workspace и ключ офлайн-журнала прежние. Кеш интерфейса привязан к адресу страницы, поэтому новый адрес загружает данные с сервера.

`sw.js` выводит из эксплуатации рабочий кеш: сразу активируется, принимает управление, удаляет только кеши файлов `samosval-shell-*` и снимает свою регистрацию. Он не перехватывает запросы, не трогает тестовые кеши, localStorage или IndexedDB и не перезагружает открытые окна автоматически. **Не очищать данные сайта для отката:** там могут быть несинхронизированные действия.

Модульные исходники и история 4.0 сохранены для расследования. Тестовая версия не изменена. Причины ошибок 4.0 в рамках срочного восстановления не исправлялись.

Проверены: точное совпадение восстановленного HTML с прежним снимком за исключением цвета; синтаксис встроенных скриптов; совпадение восстановительной страницы; модель жизненного цикла завершающего SW с сохранением тестового кеша и отсутствием операций с пользовательскими хранилищами. Старый SW не перехватывает recovery-адрес. Живые регистрация и смена в рабочей базе здесь не проверялись.
