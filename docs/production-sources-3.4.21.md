# Рабочая 3.4.21: источник истины и безопасная пересборка

28 октября 2026 исходники рабочей версии приведены **побайтно** к опубликованной `3.4.21` (сборка `d7399f63cbcbabc7`), без изменения самих исполняемых файлов, базы Firebase, правил, кеша или интерфейса. Предыдущая копия: `backup/prod-3.4.21-before-source-sync-20261028`.

## Где редактировать

- `app/src/shell.html` — разметка рабочего приложения и CSS, с маркерами подключаемых скриптов.
- `app/src/core/00-config-state.js` … `19-navigation.js` — **20 отдельных частей** общего ядра. Исполняемый `core.js` генерируется строго их конкатенацией в заданном порядке.
- `app/src/modules/*.js` — отдельные модули истории, просмотра листов, монет, игр, эффектов и остальных функций.
- `app/src/pwa.js` — автономный запуск и управление обновлением.
- `app/src/service-worker.js` — шаблон обслуживающего кеша PWA.
- `app/modules.json` — единственный список модулей, порядок их подключения, версии, источников и кешируемых файлов.

Исходные файлы прежней неудачной 4.0 удалены из текущего `app/src`, но **сохранены в истории Git и резервной ветке**. Нельзя собирать новую рабочую версию из прежних исходников 4.0. Исходники тестовой версии живут отдельно в `test-app/`; тестовый «Табель» **не включён**.

## Безопасная проверка и выпуск

Из корня репозитория:

```sh
python3 tools/build-release.py --check
```

Это проверяет, что текущие исходники собираются в **те же самые байты**, что и опубликованные `index.html`, `sw.js`, манифест и все 22 JS-бандла. Содержимое Firebase и данных браузера не затрагивается.

Сборщик по умолчанию работает в безопасном режиме `--check`. Опубликованная `3.4.21` заблокирована от перезаписи: если изменить любой её исходник и не повысить `release` в `app/modules.json`, команда `--build` прервётся с ошибкой. Следующий выпуск готовится на отдельной ветке, получает новый номер версии, новую хешированную папку и архив старой сборки. После проверки можно явно запускать `python3 tools/build-release.py --build` и публиковать файлы единым коммитом.

GitHub Actions `Production source integrity` проверяет соответствие исходников при каждом их изменении в `root`. Не очищать localStorage/IndexedDB во время обновления: там может находиться очередь несинхронизированных рейсов.

**Границы проверки:** проверяется точное совпадение выпущенных программных файлов, а не реальная работа Firebase, многопользовательских операций и Android.
