# Фотографии объектов — тестовая версия 3.1.14

Изменяется только `index-test.html`, проект Firebase `samosval-offline`, бакет `samosval-offline.firebasestorage.app`. Рабочий `index.html` и проект `samosval-test` не изменяются.

## Что нужно включить на сервере

Публикация HTML и файлов правил в GitHub **не применяет правила Firebase**. В этой поставке доступ к управлению Firebase отсутствовал; создание бакета, его тариф и правила на реальном сервере не подтверждены.

1. В Firebase Console выбрать **samosval-offline → Storage** и проверить существование указанного бакета. Если бакета нет, создать его в выбранном владельцем регионе. Не менять `storageBucket` на произвольный или рабочий бакет.
2. Проверить тариф и платёжный аккаунт. Firebase требует Blaze для доступа к Cloud Storage с 3 февраля 2026 года; включение платного тарифа требует отдельного решения владельца. Лимит программы не заменяет бюджет и уведомления Google Cloud.
3. Опубликовать `storage-object-photos-test.rules` в **Storage → Rules**. Если уже есть правила для других файлов, объединить их с новым разделом, сохранив действующие ограничения. Правила этой поставки разрешают только новый префикс фотографий.
4. Для обращения правил Storage к Firestore консоль может запросить разрешение связать службы. Подтвердить его для тестового проекта, если оно ещё не выдано.
5. Опубликовать актуальный `firestore-timesheet-test.rules` в **Firestore Database → Rules**. Добавлен запрет создавать `game_photo` через общий путь обычного пользователя; администратору запись доступна через существующее правило. Сначала проверить, что в консоли нет более новых изменений правил, которых нет в репозитории.
6. Открыть тестовую страницу под активным администратором и выполнить проверки ниже. Не использовать открытые правила `allow read, write: if true`.

Документация Firebase: [изменения требований к Storage](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024), [правила Storage и Firestore](https://firebase.google.com/docs/storage/security/rules-conditions#enhance_with_firestore).

## Хранение и доступ

- JPEG: `workspaces/main_workspace/objectPhotos/{objectKey}/{shiftId}/{photoId}/image.jpg`. Ключ объекта кодируется для пути; его название, идентификатор и смена сохранены в метаданных.
- Firestore: `workspaces/main_workspace/objectPhotos/{photoId}`; счётчик: `workspaces/main_workspace/photoStorage/usage`.
- Съёмка, отправка, удаление и настройка лимита доступны активному администратору. Просмотр через интерфейс — пользователям с доступом к архиву. Правила Storage разрешают чтение активным учётным записям, как существующие правила чтения общего рабочего пространства; публичного доступа нет.
- Снимок — JPEG до 12 МиБ, длинная сторона до 3840 пикселей. Внизу слева подпись без подложки. С флажком «Снимать без GPS» координаты отсутствуют и в подписи, и в метаданных.
- Фото и очередь отправки сохраняются в IndexedDB этого браузера, отдельно для тестового проекта. При закрытии камеры очередь остаётся; после восстановления связи отправка возобновляется. Для ошибок доступа/лимита есть ручной повтор. До подтверждения сервера фото ещё не доступно на другом устройстве. Очистка данных браузера уничтожает неотправленную очередь; готовое фото можно скачать отдельно.
- +1 монета записывается только после подтверждения JPEG хранилищем, в транзакции вместе с метаданными и счётчиком. Документ `audit/photo_{photoId}` защищает от повторного начисления при повторной загрузке или повороте этого снимка. Удаление старых фото для очистки места сохраняет уже заработанные монеты.
- Новые архивные смены хранят `sourceShiftId`; доступны «Фото объекта» и «Фото этой смены». Для старых архивных записей без исходного ID доступен весь объект.
- Фотографии и их счётчики не входят в прежний JSON-бэкап программы. Экспорт JSON не является резервной копией JPEG в Storage.

## Контроль места

Админка → Настройки → **Фотографии и место** показывает сохранённый объём, количество фото, резерв текущих загрузок и свободное место **в лимите программы**. По умолчанию лимит — 512 МиБ; администратор может его изменить. При достижении лимита новые загрузки останавливаются, локальная очередь сохраняется.

«Проверить файлы на сервере» отдельно подсчитывает фактически доступные активные объекты в префиксе фотографий с постраничным обходом. Этот подсчёт не включает другие папки, скрытые версии или мягко удалённые файлы и не переписывает счётчик во время загрузок. Общую квоту, оплачиваемый объём, soft delete, версии, жизненный цикл и бюджет нужно проверять по ссылке **Открыть Firebase Storage** / в Google Cloud Console. Удалённые файлы могут продолжать учитываться провайдером согласно политике хранения.

Очистка: выбрать фотографии → **Удалить выбранные** → подтвердить. Счётчик уменьшается только после подтверждённого удаления файла. Незавершённое удаление можно повторить. Свежую активную загрузку с другого устройства удалить нельзя; зависшая запись становится доступна для очистки через 15 минут.

## Проверка после подключения Firebase

1. В активной смене сделать фото. Дождаться «Фото сохранено в объекте · 🪙 +1». Проверить файл и метаданные в тестовом проекте.
2. Повернуть готовое фото и повторить отправку: файл заменяется, монетка повторно не начисляется.
3. Снять с выключенным GPS и флажком: снимок доступен без ожидания, текст «Без GPS», координаты не записаны.
4. Отключить сеть, сделать фото, закрыть камеру, восстановить сеть. Снимок должен уйти из очереди на сервер; монета появляется после сохранения.
5. Закрыть смену, включая смену только с фотографией, открыть архив → фото этой смены. Затем проверить весь объект и другой объект.
6. В настройках сравнить счётчик с проверкой файлов; удалить фото, обновить список и объём. Монета сохраняется. Повтор удаления не уменьшает счётчик дважды.
7. Проверить лимит загрузок, отказ Storage, ограничение доступа пользователя и вход под другим пользователем: нет ложного сообщения об успешной загрузке или начисления монеты.

Локально проверены синтаксис скриптов, камера с моделями аппаратных API, JPEG на реальном Canvas, очередь и транзакции с моделями Firebase/IndexedDB, начисления и фильтры рейтинга, повторные загрузки, удаление и лимит. Реальная камера Samsung и серверный цикл требуют проверки на устройстве и подключённом тестовом Firebase.
