# GitHub из OpenCode — рабочий процесс

Версия 1, 2026-10-31. Добавлены безопасная API-утилита и команда `/github-pr`.

## Постоянный механизм

`node tools/github-pr.cjs` использует Node.js 22+ и существующий Git credential
helper. GitHub CLI не требуется. Токен читается через `git credential fill`
только в память процесса: не передаётся аргументом, не записывается в проект,
не выводится. Не запускайте эту команду под трассировкой окружения/отладчиком.
Нужны сеть, Git, настроенная identity и сохранённые учётные данные GitHub.

- `node tools/github-pr.cjs check` — только GET: авторизация, репозиторий, PR #73.
- `node tools/github-pr.cjs plan` — только GET: дополнительно поиск открытого PR
  текущей ветки. Это не POST и не гарантированная проверка права создания PR.
- `node tools/github-pr.cjs create "Заголовок" /путь/описание.md` — явное создание
  **draft PR в root**, только при чистом дереве и совпадении HEAD с GitHub.
  При существующем открытом PR выводится его адрес вместо создания нового.
  Защищённые production/серверные пути, Firebase rules и типичные файлы секретов
  блокируются; это дополнительная защита, а не полноценный сканер секретов.
  Нет автоматического push, merge или изменения настроек GitHub.
  Создание PR может запустить существующие Actions по событию pull_request.

`/github-pr` — сохраняемая команда OpenCode из `.opencode/commands/github-pr.md`.
Это шаблон для агента, а не защитная песочница. Утилита также не заменяет проверку
изменений и согласование защищённых действий. AGENTS.md остаётся неизменным.

## Обычная задача

1. Прочитать AGENTS.md и PROJECT_CONTEXT.md. Проверить `git status --short --branch`,
   изменения пользователя, реальный код и существующие тесты. Не выводить credentials.
2. При чистом дереве: `git fetch origin root`, затем
   `git switch -c feature/краткое-имя origin/root`.
   Не работать в root или ветке PR #73. Пока #73 не слит, для нового checkout
   отдельно обеспечить доступ к его правилам; не сливать #73 самостоятельно.
3. Изменить только согласованные файлы. Не трогать рабочий index.html,
   PostgreSQL, Firebase, NAS и продакшен без отдельного разрешения.
4. Выполнить подходящие тесты по затронутому модулю, `git diff --check`.
   Для UI обязателен Playwright MCP на изолированной странице с тестовыми данными.
   Никогда не проверять реальные погрузки/смены на продакшене.
   Offline-first, конкуренцию, аудит и синхронизацию проверять, когда затронуты.
5. Просмотреть diff, явно выбрать файлы через `git add путь...`, проверить
   `git diff --cached`, затем `git commit -m "тип: описание"`. Не использовать
   `git add .` вслепую. Не включать токены и пароли.
6. До push изучить текущие `.github/workflows/` и настройки Pages: push может
   автоматически запустить публикацию даже без ручного deploy.
   Только при разрешённом безопасном push: `git push -u origin HEAD`.
7. Составить описание по `.github/pull_request_template.md`; выполнить `plan`,
   затем явно запрошенный `create`. Указать успешные и непроведённые проверки.
8. Показать URL PR, commit SHA, результаты и риски. **Не merge и не deploy**.

## Проверка механизма без публикации

```sh
node --check tools/github-pr.cjs
node --test tests/github-workflow/*.test.cjs
node tools/github-pr.cjs check
node tools/github-pr.cjs plan
git diff --check
```

Это не создаёт PR, не выполняет push и не меняет root. Создание PR полностью
подтверждается только после разрешённого реального POST; GET и локальные тесты
не доказывают успешность будущего POST или прохождения GitHub Actions.

## Playwright и перезапуск

Браузер проверять реальным вызовом MCP: открыть `about:blank`, получить snapshot
и выполнить безопасное чтение DOM. Это проверка инструмента, не тест приложения.
Доступный в текущем окружении remote MCP задан глобально в
`~/.config/opencode/opencode.json` (сервер `playwright`). Не копировать адреса
авторизации или заголовки в репозиторий. Если `opencode mcp list` расходится
с реально доступными инструментами, проверить `/mcps` в самой сессии;
не считать вывод отдельного CLI доказательством отсутствия работающего MCP.

Файлы команды, утилиты и документации сохраняются на диске и читаются OpenCode
после перезапуска при открытии этого checkout. Они появятся в новом клоне/ветке
только после разрешённых commit/push и принятия PR. Сохранность credentials
и глобального MCP зависит от сохранности пользовательского каталога окружения.
