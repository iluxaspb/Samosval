## Сущности и процессы (фронтенд/линия)

- Прибытие (приезд машины на линию), погрузка, возврат после рейса, «Взял ТТН»; ходка = погрузка → следующее возвращение; ожидание = приезд → погрузка (незавершённые интервалы в среднее не входят).
- Защита от дублей: серверные проверки в `server/src/line-rules.mjs` + транзакции с блокировкой строки самосвала (`line-store.mjs`); детерминированные ID погрузок; повтор запроса не создаёт дубль (проверено живыми пробами на фиктивной машине, `docs/synology-v4-test-status.md`).
- Защитный интервал ходки: сброс таймера — только администратор (после переноса прав — старший прораб) долгим удержанием, с аудитом; старый сброс не может затереть новую погрузку (`docs/line-integrity-protocol.md`).
- Смены: дневные/ночные; время ходки задаётся/подтверждается при открытии смены, общее для всех её пользователей.
- Материалы: расходные материалы (например, асфальт, ПГС, щебень) привязываются к смене, в которой шли рейсы; материал из объёма обычных рейсов связывается со сменой автоматически (название/направление/назначение), коррекция рейса меняет объём, не создавая дубля. Принадлежность материала — выбранная при открытии смена, независимо от времени закрытия смены.
- Табель: сводные человеко-часы, своя техника получает безымянные места экипажа (поливомойка — водитель, щётка — тракторист, погрузчик — машинист, фреза — минимум два машиниста), наёмная техника — одна строка с часами без экипажа. Справочники: техника (своя/наёмная), машинисты фрезы, дорожные рабочие, ИТР.
- Сводка по объекту («Месяц» → весь период объекта с переходом месяцев), архив смен: плашки объектов → смены; отчёт полноэкранным оверлеем, сохранение листа PNG; рисование и PDF удалены (версии, зафиксированные в `docs/versioning.md`).
- Вкладка «Заявка» (правило владельца, 13.11.2026): изолированный жёстко зафиксированный адрес СЛЕДУЮЩЕГО объекта; сохраняется своей кнопкой и не меняется переходами по вкладкам. Не связывать с адресным механизмом остальных вкладок (причины ошибок 1.7.4/1.7.5 — именно в связывании).
- Офлайн-очередь: события сохраняются локально и синхронизируются при восстановлении сети; обновление PWA не должно терять неотправленные действия (`tests/pwa/update-browser.py`); совместная работа операторов через статусы линии и присутствие.
- Игровой режим: награды «первый приезд = 0, возврат после рейса = 2, погрузка = 1», одно событие — один раз; ставки настраиваются администратором; штраф назначает прораб/администратор с причиной и аудитом.

## Пользователи и права

- Роли (окончательная иерархия, `docs/test-3.3-requirements.md`): `admin` (администратор), `senior_foreman` (старший прораб, корона 👑, прежние права прораба включая сброс таймера), `foreman` (прораб, фактические права прежнего мастера, 🔧), `worker`/мастер, наблюдатель 👁, лопатёр 🪏. Значки не меняют полномочия.
- Права проверяются на сервере (default deny, матрица `role_permissions`), видимость кнопки ≠ доступ. Раздел «Безопасность» настраивает только администратор; скрытие данных должно быть серверным, не CSS.
- Вкладка «Таблицы» — в основном нижнем меню, доступ по матрице прав (нет доступа / только просмотр / редактирование), по умолчанию только администратор.
- Авторизация: Firebase Auth ID-токен (проверка подписи в `server/src/auth.mjs`) + активный пользователь в локальной `app_users`.

## Версии и PWA

- Цвет номера версии — признак канала: зелёный у рабочей, красный с подписью «тест» у тестовой; цвет не менять с темой оформления.
- Номер и история изменений видны только активному администратору (ограничение интерфейса).
- Каждая версия — отдельное PWA (свой значок/манифест/SW). Новые сборки — только штатным сборщиком `tools/build-working-test.py`; единая версия во всех источниках (shell.html, release-history.js, собранные файлы) — условие выпуска.
- Причины прошлых сбоев PWA (кратко, детали в истории релизов): (1) пересечение scope/манифестов разных версий в одном адресе — Android склеивал ярлыки и красил рабочую цветами теста; (2) ожидание версии из build-manifest без таймаутов — одна зависшая загрузка блокировала установку навсегда; (3) публикация «по факту сборки» без открытия собранной страницы; (4) удаление старых build-каталогов — застрявший на старой версии клиент получает 404 и чёрный экран (держать минимум последние сборки). Всё закрыто протоколом выпуска в AGENTS.md и механизмом принудительного обновления.

## Договорённости по интерфейсу

Сохранение ввода (не терять введённое при переходах/обновлении), сохранение фокуса и прокрутки при перерисовках — обязательные свойства экранов; проверяются браузерными тестами.
