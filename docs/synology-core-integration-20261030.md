# Подключение основного интерфейса NAS — кандидат TEST

В код основного интерфейса добавлены ветка входа через NAS-профиль, обновление состояния линии и отправка существующей устойчивой офлайн-очереди через NAS-клиент. Кэш и очередь разделены по провайдеру, origin, workspace и UID. Старые Firebase-намерения не перемаркируются. Квитанции NAS сохраняются до обновления UI; сетевые/авторизационные ошибки без бизнес-квитанции оставляют намерение pending. Побочные записи в Firestore из этого пути не выполняются.

Вход использует профиль и права NAS, без forced-admin по email. Отзыв доступа очищает видимые данные и оставляет наблюдение за профилем. Выход останавливает старый клиент, поздние результаты не применяются к новой учётке. Снимок, прочитанный до квитанции, не может откатить карточку к меньшим ревизиям.

Путь активируется только отдельной сборкой с meta test-data-provider=synology-candidate. Обычный опубликованный TEST остаётся Firebase; маркер не добавлен. NAS-переключатель по localStorage не активируется. Фоновый прежний табель не стартует в NAS-кандидате до подключения NAS-host. Страница, версия и production не опубликованы и не переключены. Это подключение к коду экранов, не завершённый релиз.

Локально: 13 проверок реальных core-обработчиков прошли; общий набор — 96 pass, 0 fail, 11 PostgreSQL-групп skipped. Модульный аудит прошёл: порядок 33 модулей, 67 исходных файлов, синтаксис, SHA256, детерминированная пересборка, production untouched. GitHub CI дополнительно выполняет аудит модульной сборки и весь серверный набор с PostgreSQL.

Общий legacy-прогон tests/pwa/run-regressions.cjs пока не зелёный. Сезонный тест ждёт roadworks, отсутствующий в каноническом source-модуле; тот же сбой воспроизводится с исходным index-test.html до этих изменений. Отдельно regression.cjs ожидает 36 анекдотов и interval, тогда как текущий source содержит 89 и счётчик действий. Исправления сезонного модуля пробовались локально для диагностики и отменены; поведение не менялось. Нужна сверка канонического source с прежним src и актуализация регрессий без отката пользовательских функций.

Формы регистрации/администрирования подключены в NAS-ветке: pending-регистрация, заявки, имена, роли, доступ, удаление и матрица прав используют NAS API. Административные операции сохраняются в отдельной очереди scope до отправки; потерянный ответ повторяется с теми же ID и ревизиями. Свежий снимок не перемаркирует неподтверждённую операцию. Проверены ожидающие решения, конфликт нового намерения с незавершённым старым и выход во время запроса.

До публикации остаются: справочники и смены, табель и presence, игровые операции и настройки, архивные мутации/история в UI, актуализация данных из действующего Firebase, изоляция всех оставшихся прямых Firestore-обращений. Нужны браузерные сценарии нескольких операторов, разрыва связи, повторного запуска PWA и отката. Firebase-репликация/failover не реализованы. Сборку нельзя объявлять полным 4.0 или включать NAS всем пользователям на основании модульных тестов.
Уточнение пользователя: фотографии удалены из проекта. Перенос фото, фотохранилище и проверки фото исключены из миграции и условий выпуска; возвращать функцию не требуется.
