# TEST Synology: границы выпуска и открытие смены

Запрос пользователя — полностью переключить и выпустить тестовую программу. Разрешение на выпуск получено. Препятствие техническое: все основные экраны ещё не используют NAS как единственный источник записи. Production не входит в выпуск, фото исключены.

Подтверждённый действующий API доступен по внешнему HTTPS через внутренний порт 18081. На нём проверены база и авторизованное чтение линии. Он реализует операции линии, табель и двухэтапное закрытие смены. Основная опубликованная TEST-страница продолжает использовать Firestore; в частности её подписки и транзакции офлайн-журнала обращаются к refs/db, а доступный клиент NAS-табеля ещё не подключён ко всему интерфейсу.

В этом этапе добавлен POST /api/v1/shifts/start и таблица workspace_objects. Администратор или роль с start_shift может открыть смену только с действующим серверным объектом. Имя объекта, имя оператора, дата Москвы и время открытия берутся на сервере. Блокировка workspace сериализует одновременные старты, квитанция обеспечивает повтор с прежним ID. Изменённое тело с прежним ID отклоняется. Незавершённое закрытие или остаточные данные линии блокируют старт; обработчик ничего не удаляет. Операция и запись аудита атомарны.

seedObjects переносит справочник из явно указанной контрольной суммы первоначального TEST-импорта только в пустую целевую таблицу. Проверяются база, проект, workspace, число и содержимое документов; payload сохраняется целиком. Это перенос исходной копии, не синхронизация с текущим Firebase. Перед установкой требуется свежая резервная копия NAS; применять seed повторно к действующему справочнику нельзя.

Новый обработчик ещё не установлен на NAS и не подключён к интерфейсу. Он не означает готовности полного релиза. Для переключения остаются серверные справочники/добавление машин на линию, профили/права и заявки, чтение архива и аналитики, общий аудит/отмена/восстановление, игровые операции и присутствие; затем подключение экрана и устойчивой очереди к одному адаптеру, актуализация данных, проверка полного цикла и PWA, резерв и откат. Политика Auto не должна включать запись в независимую резервную базу до реализации репликации и единственного владельца записи.

Тестовый релиз нельзя объявлять полностью работающим на Synology только после изменения адреса API или буквы индикатора.
