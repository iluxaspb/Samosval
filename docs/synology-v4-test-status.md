## Целевая схема

- Интерфейс остаётся на GitHub Pages.
- Synology DS923+ и PostgreSQL — основной API и данные тестовой среды.
- Firebase Authentication — вход пользователей.

- API доступен через HTTPS. Настройки DSM, сертификатов и портов в этой правке не меняются.

## Добавлено на этом этапе

`test-app/synology/line-transport.mjs` — самостоятельный модуль отправки существующей записи очереди на Synology. Опубликованный интерфейс пока его не подключает.

- ID и время операции сохраняются при повторной отправке.
- Используется Firebase ID token. При 401 допускается ровно одно принудительное обновление токена.
- HTTPS обязателен; перенаправления запрещены, чтобы токен не уходил на другой адрес.
- Сетевой сбой, тайм-аут, ошибка шлюза или повреждённый ответ означают неизвестный результат. Запись нельзя удалять из очереди: повтор отправляет те же данные с тем же ID.
- Отказ сервера по бизнес-правилам возвращается вызывающему коду как квитанция; отдельного рейса он не создаёт.

Интерфейс модуля:

```js
const transport = createLineTransport({
  baseUrl: verifiedTestApiBaseUrl,
  getIdToken: force => firebase.auth().currentUser.getIdToken(force)
});
const receipt = await transport.submit(existingQueuedOperation);
```

Пример предназначен для будущего подключения к проверенной очереди TEST. При `uncertain: true` очередь сохраняет операцию и позднее повторяет запрос. Модуль не выполняет резервные записи в Firestore: решение о переходе на резерв требует общего протокола владения записью, чтобы два сервера не приняли расходящиеся изменения.

1. Проверить запущенный тестовый проект Container Manager, версию схемы БД, локальную готовность API и HTTPS-маршрут. Доступа к действующей сессии DSM в этой среде нет; развёртывание не подтверждено.
2. Подготовить импорт только тестовых профилей, прав, смен, техники и статусов; сверить количество записей и контрольные значения.
3. Реализовать чтение и живую синхронизацию с проверкой прав, открытие/закрытие смен, справочники, отмену/восстановление и аудит.
4. Перенести табель и таблицы с формулами, фото, архив, аналитику и игровые операции с сохранением действующей логики.
5. Подключить транспорт к устойчивой локальной очереди TEST и к серверным подпискам. Проверить работу нескольких операторов, офлайн и повтор после обрыва ответа.
6. Реализовать резервирование в Firebase, контроль отставания, восстановление и переключение с единственным владельцем записи. Испытать потерю Synology и его возврат.
7. Сделать резервную копию, прогнать проверки приложения и отката, затем выпустить именно тестовую 4.0. Рабочую версию выпускать только по отдельному поручению.
