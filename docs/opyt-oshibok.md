## 2. `working-test/src/pwa.js` различается между каналами

**Симптом:** после переноса сборки в прод service worker не регистрируется — нет офлайна и автообновления, телефоны не получают обновление.
**Причина:** в канале working-test `pwa.js` проверяет `location.pathname.endsWith('/index-working-test.html')`, в проде нужен `/index.html` (строка 4, `eligible`) и редирект после обновления на `./index.html` (строка ~341). При переносе файл нужно приводить к production-виду вручную.
**Что делать:** после сборки прод-комплекта сверять `git diff root -- working-test/src/pwa.js` — он должен совпадать с прод-версией байт-в-байт. Правка меняет sha256 → пересчитать RECORDS в `sw-working-test.js` и оба `build-manifest.json`. Стреляло при выпуске 1.7.22 (исправлено до публикации).

## 3. Серверные тесты ветки `release/working-test` частично красные
**Симптом:** `node --test server/tests/` на коде ветки даёт красные тесты.
**Причина:** код replica/auth-миграции ушёл вперёд тестов:

**Что делать:** это долг ветки, не продакшена (в рабочей базе `samosval_test` таблиц replica/auth-миграции нет). При следующем переносе серверных изменений из этой ветки тесты привести в порядок ДО выпуска.

## 12. Урок 23.11.2026 (выпуск 1.8.4): 404 на index-working-test.html валил установку SW — штатные обновления не работали ВООБЩЕ

**Симптом:** у владельца обновления ставились только через чистку кэша; страница восстановления писала «Обновление не выполнено: index-working-test.html 404». Приложение при этом работало (страница грузится network-first), поэтому проблема маскировалась годами.
**Причина:** RECORDS сервис-воркера включают `./index-working-test.html`, а процесс публикации клал главную страницу на Pages только как `index.html`. Install воркера качает ВСЕ записи: один 404 — и установка падает целиком, новый воркер никогда не активируется.
**Сделано:** файл восстановлен на сайте под оригинальным именем (дублирует index.html); после публикации проверены все 142 записи RECORDS по URL+SHA-256. Владелец подтвердил: автообновление 1.8.4→1.8.5 сработало штатно, без чистки кэша.
**Что делать при каждом выпуске working-test:** после пуша Pages обязательно прогонять полную сверку RECORDS (все URL → 200 + SHA совпадает), а не только version.json. Обязательный шаг добавлен в порядок выпуска. Заодно: `tools/verify-working-test.py` хранит устаревший REQUIRED_VERSION='1.7.22' и красный на любом 1.8.x — эталон актуализировать отдельной задачей.
