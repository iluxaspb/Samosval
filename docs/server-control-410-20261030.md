# TEST 4.1.0 — центр управления и обновление приложения

Согласовано пользователем 30.10.2026: выполнить в следующем тестовом выпуске.
Рабочие `index.html`, `app/`, Firebase Rules и production-данные не меняются.

## Поведение для пользователей

- Все роли видят только номер сборки, без слова «Версия».
- Историю изменений открывают только активные администратор и **прораб (`foreman`)**.
  Мастер, лопатёр и наблюдатель историю не открывают.
- При запуске, возвращении в приложение, восстановлении связи и каждые две минуты
  видимое приложение проверяет опубликованный манифест GitHub Pages.
- Если манифест отличается от открытой сборки, появляется «Доступно обновление» → «Установить».
- Окно установки показывает этапы и фактическое количество полученных и проверенных
  файлов. Проценты относятся к файлам, не к байтам и не ко всей длительности установки.
- Наличие неподтверждённых рейсов, изменений NAS, сохранения табеля или конфликтов
  останавливает перезапуск с понятной причиной. Данные не очищаются.
- Активируется только полный комплект файлов с SHA-256. Очистка старых программных
  кешей вынесена из активации, сохраняются два предыдущих кеша. Другие окна не закрываются.
  Перезапускается только окно, в котором пользователь подтвердил установку.
- В режиме табеля «Ввод только чисел»: первое нажатие выбирает ячейку,
  второе на ту же выбранную ячейку открывает цифровую панель. Выбор другой ячейки
  начинает последовательность заново. Выделение уголком и отдельная кнопка «Заполнить автоматически» доступны в числовом режиме. В полном режиме добавлены буквенные заголовки и номера строк также у связанного листа; нажатие выделяет всю строку/столбец. Компактное контекстное меню содержит только применимые действия. На свободных листах доступны объединение и разъединение с защитой заполненных соседних ячеек. Панель границ содержит десять пресетов, 1–4 px, сплошную/штриховую/точечную/двойную линии, цвет и предпросмотр; оформление передаётся в Excel/PDF.

## Центр управления

Админка → Сервер: обзор, ресурсы, обновления, копии, объекты, журнал.
API проверяет Firebase ID token и **текущую** активную роль `admin` при каждом обращении.
Прораб не получает управления сервером вместе с правом просмотра истории.

- Состояние и версия API, время работы, размер PostgreSQL.
- Свободное место и объём NAS, память NAS, load average 1/5/15 минут.
- Запросы, p95 последних 500 ответов и последние HTTP 5xx — с момента старта API.
- Зарегистрированные, допущенные пользователи и заявки. Не выдаётся за число online.
- Объекты и открытые смены, последние копии данных приложения.
- Полные копии PostgreSQL с обязательным тестовым восстановлением в отдельную БД.
- Проверка GitHub, установка API, возврат предыдущего API, перезапуск API.
- Задания и этапы остаются на NAS после закрытия приложения.
- Запрос команды использует стабильный ID: потерянный ответ повторяется без второго задания.
- Устаревшие данные и отсутствие heartbeat службы блокируют действия.

SMART, RAID, температура, удаление файлов, управление DSM, сетевые настройки и
универсальная root-консоль **не реализованы**. Неизмеренные показатели явно обозначены.
Нет полного списка очередей других устройств: приложение показывает локальную очередь.
Нет автоматического восстановления БД поверх текущих рейсов при откате кода.

## Отдельная служба TEST

`server/updater/agent.mjs` запускается постоянно в отдельном контейнере без публичных
портов. Только этот контейнер имеет Docker socket. Это привилегированный компонент,
его исходники и bootstrap проверяются отдельно от клиентского интерфейса.
Main API не получает Docker socket или пользовательские команды оболочки.

Служба обновляет только `samosval-test-candidate/api`, проверяет PostgreSQL
`samosval-test`, использует фиксированный compose-файл и внутреннюю TEST-сеть.
Один advisory lock PostgreSQL допускает только один worker. Задания и их поля
повторно проверяются worker; произвольные пути/URL/команды не принимаются.

Перед update/rollback: новый полный dump, `pg_restore --list`, восстановление в
временную БД и контрольный запрос основных таблиц. Ошибка подготовки не меняет API.
Перед переключением на диск записывается предыдущий image ID. Неудачный запуск
возвращает старый API; перезапуск worker восстанавливает незавершённое переключение.
Данные БД при возврате API остаются текущими. Старые образы и копии не удаляются автоматически.
До первого совместимого обновления кнопка возврата API недоступна: прежний сервер
4.0.2 не поддерживает центр управления. Его образ сохраняется в файлах аварийного
восстановления bootstrap; автоматический возврат при сбое установки работает.

## Релизы GitHub

`releases/nas-test.json` публикуется **отдельно после успешного CI исходного коммита**.
Обновлятор читает только `iluxaspb/Samosval`, `root`, фиксированный путь manifest,
а исходники скачивает по полному commit SHA. Для него необходим успешный запуск
`.github/workflows/synology-server-tests.yml` для этого SHA.

Манифест содержит SHA-256 и размер каждого `src/*.mjs`, отпечатки dependencies и SQL.
Протокол 1 допускает обновления исходников API с прежними зависимостями и схемой.
Изменение схемы, зависимостей или самой службы требует отдельного bootstrap;
кнопка приложения не запускает произвольные миграции/скрипты.

Подготовка после коммита проверенных исходников:

```sh
node server/scripts/prepare-control-release.mjs 4.1.1
```

Изменённый манифест коммитится отдельно и проходит review. В текущем выпуске
не следует предлагать пользователю неподтверждённый будущий релиз.

## Однократная установка

```sh
python3 server/scripts/package-control-bootstrap.py /absolute/path/control-bootstrap-410.zip
```

Пакет содержит только исходники, SQL 013, compose, baseline и контрольные суммы.
Никакие `.env`, dump или данные пользователя в пакет не попадают.
На NAS распаковать в новый каталог под `/volume2/docker/samosval-test-control/`.
Запустить `updater/install-test-control.sh` в ручной root-задаче DSM (расписание отключено).
Скрипт проверяет суммы, контейнеры, базу и свободное место, строит образы,
создаёт и проверяет резерв, применяет только добавляющую SQL 013, переключает API
и запускает независимую службу. При ошибке возвращает прежний API.
Факт установки подтверждается `BOOTSTRAP_TEST_READY`, heartbeat и входом администратора.
До этого сборку нельзя объявлять полностью установленной на NAS.
