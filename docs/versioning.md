# Версии рабочей и тестовой программы

Правило владельца от 25 октября 2026 года действует для следующих выпусков:

- **Рабочая версия и релизы:** номер версии зелёный (`#22c55e`).
- **Тестовая версия:** номер версии красный (`#e11d48`), рядом с номером сохраняется подпись «тест».

Цвет обозначает канал выпуска. Его нельзя менять вместе с темой оформления, сезонными эффектами или произвольным повышением номера версии. История изменений открывается нажатием на номер, как и прежде.

## Рабочая версия 4.0

Рабочая страница — `index.html`, исходники — `app/src/`, порядок модулей — `app/modules.json`. Сборка из корня репозитория: `python3 tools/build-release.py`. Она создаёт `index.html`, `app/build/<hash>/`, `sw.js` и `app/build-manifest.json`. В 4.0 переносится принятая владельцем модульная тестовая версия. Табель, его вкладка, права, настройки и обработчики остаются в тестовой версии и не входят в рабочую сборку.

Номер текущего рабочего релиза задаётся первой записью массива `releases` в `app/src/features/release-history.js`. Этот модуль создаёт кнопку версии и берёт её номер из первой записи истории. Тот же номер должен быть указан в начальной разметке `app/src/shell.html`, чтобы до загрузки JavaScript пользователь видел правильную версию. Зелёный цвет задаётся в оформлении оболочки и сохраняется при создании кнопки модулем истории.

## Тестовая версия

Тестовая страница — `index-test.html`, исходники — `test-app/src/`, сборка — `python3 tools/build-test.py`. Номер в начальной разметке `test-app/src/shell.html` и в кнопке, которую создаёт `test-app/src/features/release-history.js`, должен совпадать. Оформление номера остаётся красным. Публикация рабочего релиза не превращает тестовую страницу в рабочую и не переносит её данные в рабочую базу.

## Порядок следующего выпуска

1. Обновить номер и описание выпуска в исходниках истории, синхронизировать номер начальной разметки.
2. Собрать нужный канал штатным сборщиком. Готовые файлы в `build/` и сгенерированный HTML вручную не редактировать.
3. Проверить номер и цвет после полной загрузки страницы: модуль истории заменяет исходную подпись кнопкой. Проверить оба канала и открытие истории версий.
4. Опубликовать HTML, Service Worker, манифест и файлы новой сборки одним коммитом. Сохранить файлы предыдущей сборки для ещё открытых окон.

Смена номера и цвета не меняет Firebase-проект, права, локальную очередь и пользовательские данные. Рабочий проект остаётся `samosval-test`; тестовый — `samosval-offline`.
