# Версии рабочей и тестовой программы

Правило владельца от 25 октября 2026 года действует для следующих выпусков:

- **Рабочая версия и релизы:** номер версии зелёный (`#22c55e`).
- **Тестовая версия:** номер версии красный (`#e11d48`), рядом с номером сохраняется подпись «тест».

Цвет обозначает канал выпуска. Его нельзя менять вместе с темой оформления, сезонными эффектами или произвольным повышением номера версии. С 3.4.3 (рабочая) и 3.1.19 (тестовая) номер и история изменений в интерфейсе доступны только активному администратору после проверки прав. Индикатор синхронизации остаётся для всех. Это ограничение интерфейса: содержимое общедоступного HTML и истории GitHub нельзя сделать секретным одним клиентским JavaScript. Публикацию/изменение исходников ограничивают отдельные права доступа GitHub.

## Текущая рабочая версия: 3.4.21

28 октября 2026 проверенная тестовая 3.4.21 перенесена в рабочий `index.html` без Табеля. Рабочая Firebase, офлайн-очередь и PWA-установка сохранены. Добавлены новые листы и безопасное обновление приложения; см. `releases/3.4.21/RELEASE.md`.

## Ранее выпущенная рабочая версия: 3.4.6

В 3.4.6 просмотр архивного листа открывается в полноэкранном оверлее по нажатию на сам лист; есть увеличение, перетаскивание, подгонка целиком и жест двумя пальцами. Значок 📄 для переключения обычного/ГАИ-листа находится внизу справа, без текстовой подписи. История версии отражает изменения для администратора. Рисование остаётся отключённым; архивные PNG и сортировка данных не меняются.

## Предыдущая рабочая версия: 3.4.5

В 3.4.5 удалены инструменты ручного рисования на листах сводки, ГАИ и архива. Кнопки, обработчики и холсты рисования исключены; PNG создаётся по самому листу. История изменений, доступная администратору, обновлена. Содержимое отчётов, автоматические отметки ТТН, масштабирование и права сохранены. `index.html` и `recovery-3.4.html` идентичны.

## Предыдущая рабочая версия: 3.4.4

В 3.4.4 исправлено отображение зелёного номера версии и истории обновлений у активного администратора: атрибут проверки роли теперь явно получает значение `1`, ожидаемое стилем. Доступ остальных ролей к номеру и истории остаётся закрытым. `index.html` и `recovery-3.4.html` синхронно обновлены; данные и работа PNG не затронуты.

В 3.4.3 архивные PNG создаются по видимому листу без сортировки и смешивания архивов, без обрезки при большом числе рейсов. Сохраняются рукописные отметки и режим ГАИ. Номер версии и журнал изменений в интерфейсе видит только активный администратор. `index.html` и `recovery-3.4.html` синхронизированы.

Выпуск 4.0 отозван по сообщению владельца о поломке регистрации и закрытия смены. Рабочий источник сейчас — восстановленный однофайловый `index.html`; отдельная `recovery-3.4.html` содержит тот же код для обхода кеша. В 3.4.1 исправлено закрытие смены, отчёты переведены на PNG, в MAX оставлены только текстовые уведомления. Цвет рабочей версии остаётся зелёным. Модульная сборка ниже сохранена для расследования и не должна публиковаться автоматически.

В 3.4.2 добавлены настройки монет за погрузку, возвращение после погрузки и «Забрал ТТН» (по умолчанию 1 / 2 / 0). Администратор задаёт целые числа от 0 до 10 000 в блоке «Игровой режим → Монеты за действия». Ставка фиксируется в истории подтверждённого действия; у старых записей остаются прежние начисления. Для отложенных действий учитывается время постановки в очередь. Каждая версия использует настройки своего Firebase-проекта.

Перед изменением создана резервная ветка `backup/production-before-rewards-20261026` на коммите `d355556c72f81f6f104aa3bac9b28f584dbc0c9a`. Она хранит прежние рабочие `index.html` и `recovery-3.4.html`; новые версии этих двух файлов должны оставаться одинаковыми. Для отката рабочей страницы восстановить оба файла из резервной ветки отдельным коммитом. Не сбрасывать всю ветку `root`: это могло бы удалить последующие независимые изменения. Резервная ветка содержит код, а не копию Firebase или локальных данных телефона.

## Отозванная модульная версия 4.0

Рабочая страница — `index.html`, исходники — `app/src/`, порядок модулей — `app/modules.json`. Сборка из корня репозитория: `python3 tools/build-release.py`. Она создаёт `index.html`, `app/build/<hash>/`, `sw.js` и `app/build-manifest.json`. В 4.0 переносится принятая владельцем модульная тестовая версия. Табель, его вкладка, права, настройки и обработчики остаются в тестовой версии и не входят в рабочую сборку.

Номер текущего рабочего релиза задаётся первой записью массива `releases` в `app/src/features/release-history.js`. Этот модуль создаёт кнопку версии и берёт её номер из первой записи истории. Тот же номер должен быть указан в начальной разметке `app/src/shell.html`, чтобы до загрузки JavaScript пользователь видел правильную версию. Зелёный цвет задаётся в оформлении оболочки и сохраняется при создании кнопки модулем истории.

## Тестовая версия: 3.1.20

В 3.1.20 отключено ручное рисование поверх листов во всех разделах; архивный лист открывается полноэкранным оверлеем с масштабированием, перетаскиванием и переключением обычного/ГАИ-листа по значку 📄 внизу справа. Исправлен красный индикатор версии у активного администратора: атрибут проверки роли теперь содержит значение `1`. История для админа обновлена, для остальных пользователей скрыта. Изменения публикуются как согласованная сборка тестового PWA с отдельным офлайн-кэшем.

### Предыдущая тестовая версия: 3.1.19

В 3.1.19 тот же алгоритм PNG применён к тестовому архиву; номер/история версий показаны только активному администратору. Тестовые файлы должны быть опубликованы только в составе новой согласованной PWA-сборки (HTML, модули, хешированный манифест и Service Worker).

Тестовая страница — `index-test.html`, исходники — `test-app/src/`, сборка — `python3 tools/build-test.py`. Номер в начальной разметке `test-app/src/shell.html` и в кнопке, которую создаёт `test-app/src/features/release-history.js`, должен совпадать. Оформление номера остаётся красным. Публикация рабочего релиза не превращает тестовую страницу в рабочую и не переносит её данные в рабочую базу.

В 3.1.18 добавлены те же три настройки монет, что в рабочей 3.4.2. Камера, фотоальбомы и загрузка фотографий удалены из активной сборки. Старые файлы сборок остаются для уже открытых клиентов. Сохранённые фото, заработанные ранее фото-монеты и очереди рейсов не удаляются. Новый Service Worker активируется после закрытия старых окон тестовой версии; очищать данные сайта для обновления не нужно.

## Порядок следующего выпуска

Пока действует однофайловая версия, править `index.html` и синхронно `recovery-3.4.html`, включая номер в разметке, кнопку и первую запись истории. Модульный сборщик для рабочего hotfix не запускать. Следующая последовательность относится к модульным каналам:

1. Обновить номер и описание выпуска в исходниках истории, синхронизировать номер начальной разметки.
2. Собрать нужный канал штатным сборщиком. Готовые файлы в `build/` и сгенерированный HTML вручную не редактировать.
3. Проверить номер и цвет после полной загрузки страницы: модуль истории заменяет исходную подпись кнопкой. Проверить оба канала и открытие истории версий.
4. Опубликовать HTML, Service Worker, манифест и файлы новой сборки одним коммитом. Сохранить файлы предыдущей сборки для ещё открытых окон.

Смена номера и цвета не меняет Firebase-проект, права, локальную очередь и пользовательские данные. Рабочий проект остаётся `samosval-test`; тестовый — `samosval-offline`.
