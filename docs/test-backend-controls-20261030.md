# TEST 3.4.63 — индикатор сервера и выбор режима

Подготовка интерфейса на базе ветки миграции. Основная опубликованная TEST-страница ещё не переключается на NAS этим изменением.

- Кнопка существующей диагностики в шапке теперь содержит читаемую букву F при подтверждённой работе Firebase, О при офлайне, … до подтверждения и ! при ошибке. Firebase Auth не используется как подтверждение источника данных.
- В Админ → Настройки → Сервер данных видны три режима. Только Firebase и Автоматически сохраняются отдельно для UID, тестового проекта и workspace на этом устройстве. Сейчас обе доступные политики используют единственный действующий Firebase-адаптер.
- Только Synology явно недоступен до подключения полного интерфейса. Попытка через обработчик отклоняется, сохранённое или изменённое вручную значение synology не активирует NAS. Проверка здоровья NAS не выдаётся за готовность интерфейса.
- Настройка доступна лишь активному администратору после загрузки прав. При отзыве прав блок скрывается и обработчик больше не сохраняет выбор.
- Режим не очищает очередь, не переключает подписки и не записывает бизнес-данные. Автоматическое переключение между независимыми Firebase/NAS не реализуется этим изменением.
- Production, Firebase Rules, NAS и внешний маршрут не меняются.

Проверки: controller.cjs (права, изоляция аккаунтов, офлайн/ошибки, запрет ложного NAS, ошибки хранилища), текущая модульная сборка/контрольные суммы/детерминизм, 97 тестов табеля, существующие проверки PWA и игровых начислений. browser.py проверяет реальные исходники шапки/карточки и обновления статуса на 320/393/915 пикселях без подключения к Firebase; прогон включён в CI. Локально Chromium отсутствует, поэтому результаты визуальной проверки должны подтверждаться CI отдельно.
