# Эталон листов «Сводка» и «Архив» — TEST 3.4.17

В рамках каждой смены самосвалы сортируются **сверху вниз по времени первой погрузки**; без рейсов — внизу. Рейсы каждого самосвала отображаются **слева направо по времени загрузки**. Порядок записей в Firestore на результат не влияет. При одинаковом времени используется идентификатор записи для стабильности.

В графе «Самосвал» после объёма показывается число рейсов за смену: `24 м³ / 2 р`, `12 м³ / 1 р`, `0 м³ / 0 р`. Рядом с объёмом не пишется полное слово «рейс/рейсов». Правило применяется к обычному листу «Сводка», к листу выбранной закрытой смены в «Архиве» и к PNG-экспорту отчёта. Отдельный лист ГАИ с показателем «Рейсов: N» оставлен без изменений, поскольку для него не показывается объём в кубометрах.

Контрольный пример: самосвал А — погрузки 09:00 и 10:00, Б — 09:30, В — без рейсов. Строки: А, Б, В; столбцы самосвала А: 09:00, 10:00. Значения в графе «Самосвал»: А — `24 м³ / 2 р`, Б — `12 м³ / 1 р`, В — `0 м³ / 0 р`. В архиве исходный порядок записей может быть перемешан, но отображение совпадает со «Сводкой».

Изменения затрагивают только **тестовую** `index-test.html` и её исходники в `test-app/source/`. Рабочая `index.html`, рабочая база и Firestore Rules не изменяются.

Выпуск 3.4.17 переиспользует неизменённые хешированные скрипты из 3.4.16 и публикует три обновлённых JS-модуля под новым адресом; запись об этом есть в `test-app/build-manifest.json`. Следующий штатный запуск `python3 tools/build-test.py` соберёт всё заново из обновлённых исходников.
