## Следующее необходимое действие: отдельная служебная учётная запись

Google/Firebase Console открыт и вход подтверждён. Предлагаемое имя samosval-test-reserve, проект samosval-offline, роль roles/datastore.user (только данные Firestore этого TEST-проекта). Не выдавать Owner, Editor, Firebase Admin, управление Auth, Storage или production. Постоянный JSON-ключ требует отдельного подтверждения пользователя; он должен храниться только на NAS в закрытом файле с read-only mount в контейнер, а не в Git, localStorage, Library или логах. Передать путь GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/firebase-reserve.json, не читать/печатать ключ моделью. После выдачи доступа выполнить одноразовую выгрузку и проверку, затем реализацию экономной постоянной репликации и актуального Firebase-адаптера.

Одноразовый скрипт требует RESERVE_UPLOAD_CONFIRMATION=samosval-offline/main_workspace, FIREBASE_PROJECT_ID=samosval-offline, POSTGRES_DB=samosval_test, обычные переменные подключения PostgreSQL и путь к служебному ключу. Он не меняет данные NAS, не запускается по таймеру, не выдаёт ни одному серверу право записи и не включает failover. Нельзя ставить полные snapshots на частый таймер без расчёта квот и хранения. Сначала необходим журнал изменений, затем ограждение записей обоих серверов, проверка нескольких операторов и обратного перехода.

## Автоматическая подготовка служебного аккаунта

Добавлен `server/scripts/reserve-identity-setup.mjs`. По умолчанию и с `--plan` он только выводит план, не обращаясь к Google. С `--apply` использует уже авторизованный официальный Google Cloud CLI: проверяет выбранного оператора, активность samosval-offline, существующий аккаунт и его прямые роли проекта, создаёт аккаунт при отсутствии, добавляет только roles/datastore.user и читает права обратно. Эта роль действует на данные Firestore всего TEST-проекта, а не на отдельную коллекцию. Роли Owner/Editor, условные или лишние прямые привязки вызывают остановку для проверки; унаследованные права этим скриптом не аудитируются. Политика проекта целиком не заменяется.

План: `node server/scripts/reserve-identity-setup.mjs --plan`.

Применение на доверенном хосте с уже настроенным gcloud требует явных переменных:

```sh
RESERVE_SETUP_CONFIRMATION=samosval-offline/samosval-test-reserve \\
RESERVE_OPERATOR_ACCOUNT='your-google-account' \\
node server/scripts/reserve-identity-setup.mjs --apply
```

Скрипт не запускает вход, не создаёт и не передаёт приватный ключ, не настраивает credential на NAS, не устанавливает контейнер и не включает резерв или failover. Отдельный этап выдачи и закрытого размещения серверного credential остаётся необходимым. Если Google Cloud недоступен либо gcloud не авторизован, автоматизация не обходит это ограничение.

Проверены синтаксис, режим плана и шесть локальных тестов с подставным CLI: ограничения проекта и оператора, создание, повтор без дубликатов, лишние права, отключённый аккаунт, повтор после потери ответа IAM. На реальном Google Cloud скрипт пока не запускался: в текущей среде gcloud отсутствует, а IAM и встроенный Cloud Shell возвращают Site Unavailable. Опубликованная TEST и рабочая версия не изменены.

Команды сверены с официальной документацией: https://docs.cloud.google.com/iam/docs/service-accounts-create .
