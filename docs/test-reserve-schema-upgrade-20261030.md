# TEST 4.1.1 — подготовка установки PostgreSQL outbox из админки

**Статус на 30.10.2026:** черновик PR №68; НЕ УСТАНОВЛЕНО на Synology.
Продуктивная версия `index.html`, данные production, Firebase Rules и домены не меняются.
PR №62 с автоматическим переключением — отдельная, пока неготовая функция.

## Почему потребовалась отдельная подготовка

Работающая служба управления NAS 4.1.0 устанавливает через кнопку
«Обновить сервер» **только** файлы `server/src/*.mjs`. Она намеренно
отказывает при изменении SQL-схемы и не умеет обновлять сам контейнер
управления. Поэтому попытка включить журнал только нажатием кнопки 4.1.0
не установит SQL и не должна объявляться готовым релизом.

В PR №68 на базе актуального `root` подготовлены:

- тестовая аддитивная SQL-миграция `014_reserve_outbox.sql` с 39
  транзакционными триггерами, gapless commit-order cursor и таблицей
  подтверждённой реплики;
- контролируемый одноразовый запуск **только** управляющего контейнера
  `samosval-test-control:4.1.1` (без переключения API или базы);
- расширенный формат проверенного релиза: допустима исключительно
  `sql/014_reserve_outbox.sql`, с SHA-256 и точной старой схемой,
  а не произвольный SQL из браузера;
- в новом worker: проверка точного коммита и GitHub CI, резервная
  PostgreSQL-копия и реальное восстановление в отдельную БД, **пробное**
  применение 014 на восстановленной БД, проверка 39 триггеров,
  и только затем транзакционное применение к `samosval_test`;
- проверка живого API и возврат предыдущего Docker-образа API при ошибке
  запуска. SQL 014 аддитивный: **автоматически откатывать базу к старому
  дампу запрещено**, поскольку это удалило бы вновь подтверждённые рейсы.

## Необходимая последовательность после зелёного CI

1. Проверить исходный коммит и собрать пакет проверяемой версии
   `package-control-bootstrap.py`. Включены SHA256SUMS и установка
   `updater/upgrade-test-control-worker.sh`. В архив не входят ключи,
   токены и живая база.
2. Разместить пакет на доверенном Synology и **один раз** выполнить
   скрипт через администратора DSM/Планировщик задач. Скрипт проверит
   контрольные суммы, что все три контейнера относятся к TEST, и создаст
   образ управляющего контейнера из действующего API.
   **Это пока не выполнено.** Обязательно подтвердить
   `TEST_CONTROL_WORKER_411_READY` и новый heartbeat.
3. Только после этого подготовить отдельный проверенный релиз API,
   привязанный к коммиту с зелёным CI, используя
   `prepare-control-release.mjs 4.1.1 --with-outbox-migration`.
   Не подменять установленный манифест без подтверждения исходных хешей.
4. Через TEST-админку выполнить «Проверить GitHub», затем
   «Обновить сервер». Новый worker обязан сделать и восстановить
   полную резервную копию, репетировать 014 на восстановленной БД,
   проверить PostgreSQL, применить SQL только к `samosval_test`
   и проверить готовность нового API.
5. Проверить двойной ввод двумя операторами, табель/архив/отмены,
   повтор действий, долгие смены, офлайн-очередь и журналы.
   Только затем отдельно готовить Firebase credentials, bootstrap
   контрольной копии, минутный сервис, общую write authority,
   аварийный переключатель и полноценное восстановление NAS.

## Чего этот шаг НЕ делает

- Не выдаёт Firebase права записи, не включает резервирование, таймер,
  S/F-переключение и не гарантирует восстановление NAS после аварии.
- Не устанавливается автоматически в текущий управляющий контейнер 4.1.0.
- Не меняет работающую TEST-страницу, пока нет отдельного проверенного
  клиентского релиза.
- Частый heartbeat и показатели CPU/памяти в `server_control_state`
  намеренно исключены из outbox, поэтому пустая смена не создаёт пакеты
  только из-за мониторинга. Остальные реальные изменения, в том числе
  служебные события обновления, могут создавать записи Firebase.

**Контроль безопасности:** если не подтверждены версия worker, исходный
SQL hash, восстановленная копия и CI, кнопка обновления не должна
продолжать миграцию. При неудаче установка останавливается, а API
возвращается к предыдущему образу. Текущие данные PostgreSQL не
перезаписываются восстановленным старым дампом.
