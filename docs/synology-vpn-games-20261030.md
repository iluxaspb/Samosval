## Дополнения к PR #65

- readGames передаёт только поля history, которые использует расчёт монет: без тяжёлых HTML-отчётов, табелей и справочников внутри before/after. Исходные записи, серверный расчёт, транзакции и квитанции не меняются. Регрессия сравнивает полный результат calculate, включая движения, штрафы, отмены, архивирование и разные scope. Синтетический тяжёлый пример уменьшается более чем в 100 раз; это не измерение живого пользовательского ответа.
- Успешное серверное подтверждение slot/Mario принимается немедленно. Полная история обновляется в фоне. Потеря фонового ответа не превращает уже завершённую игру в ошибку. Локальный head/player обновляется только из подтверждения NAS, не из случайного броска клиента.
- Пол раунда не даёт старому GET отменить подтверждённый результат. Временный сбой чтения сохраняет уже подтверждённый кошелёк. Начальная загрузка без подтверждения, 401/403, смена роли/аккаунта и отключение доступа по-прежнему запрещают использование неподтверждённого состояния. Каждая ставка требует настоящей серверной транзакции.
- Браузерный Firebase-emulator стенд теперь явно выбирает Firebase fixture provider и обслуживает три NAS-модуля из PWA-манифеста. Ранее он падал на 404 connection-check.mjs до запуска браузерных сценариев. Этот стенд не выдаётся за живую NAS/VPN проверку; транспорт и NAS покрыты отдельными тестами, живая проверка требуется отдельно.

Изменения ещё требуют успешного CI, установки API и проверки опубликованного клиента. Ни создание Firebase-резерва, ни автоматический failover не заменяют эту правку. Физический телефон/VPN в среде агента не воспроизводится; после установки пользователь должен проверить тем же VPN. Кеш/IndexedDB/очереди пользователя не очищать.
