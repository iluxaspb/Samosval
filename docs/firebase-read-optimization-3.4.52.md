# Тестовая 3.4.52: объединение выполняющихся чтений

Меняются только test-app/tabel-v2/store.mjs и новый read-flight.mjs; тестовые номер/история, сборка и проверки обновлены. Рабочая программа и правила Firebase не меняются. Резервные HTML, SW и манифест сохранены в releases/3.4.52, предыдущие сборки сохранены.

Объединяются только одновременно выполняющиеся одинаковые серверные чтения документов, страниц объекта и полной истории внутри одного экземпляра подключения. Каждый потребитель получает свой результат преобразования неизменяемого SDK-снимка. Контекст пользователя/проекта/роли/прав входит в ключ. Ответ сразу удаляется из объединителя после завершения или ошибки: TTL, задержек обновления и постоянного кеша нет. На старте/завершении локальной транзакции и каждом входящем серверном снимке ожидающие чтения исключаются из объединителя: новые запросы не присоединяются к ранее начатым.

Все транзакционные проверки, записи, operation receipts, повторные отправки, конфликты и реальные подписки сохранены. Не изменены состав/фильтры запросов, страницы по 200 записей, будущие/ночные смены, tombstones, журнал, права, Excel/PDF, присутствие и локальные данные.

Намеренно не выполнялись потенциально рискованные изменения: ограничение истории/архива, объединение игровых подписок с журналом, отключение подписок скрытых вкладок, замена серверных проверок локальным кешем и сокращение транзакций. Доказательство экономии относится к числу вызовов SDK в сценарии перекрывающихся чтений, а не к обещанному проценту снижения счёта Firebase: SDK также может самостоятельно объединять часть запросов.

Проверено: 56 модульных тестов; два браузера с реальным SDK Firestore и эмулятором (синхронизация, офлайн-конфликты, потеря подтверждения, права и общая история); мобильный ввод формул и диапазонов; настоящие сенсорные жесты; импорт/экспорт XLSX и многостраничный PDF; совместное выделение двух пользователей; открытие без сети и восстановление объекта; рабочий канал не изменён.
