# Клиентский слой Synology — TEST, 30.10.2026

Новый test-app/synology/session-client.mjs обслуживает сессию, чтение линии/архива/истории и отправку операций линии/отмены/восстановления. Модуль ещё не подключён к опубликованному интерфейсу. Это подготовка подключения экранов, а не завершённый TEST-релиз.

Клиент привязан к конкретному объекту Firebase Auth user. На каждом await проверяются прежний пользователь и остановка клиента; stop() вызывается при любом auth-переходе. Старые ответы после выхода, замены учётки или отписки не должны применяться к интерфейсу. Таймаут охватывает также получение токена. При 401 выполняется ровно одно обновление токена. Cookies, referrer, redirects и кэш HTTP не используются.

scope — JSON из провайдера synology, HTTPS origin, workspace и UID. Очередь и кэш приложения должны иметь отдельные ключи для этого scope. submitLine и submitHistory требуют сохранённый operationScope; записи старой Firebase-очереди нельзя маркировать новым scope автоматически. Исходные ID и тело операции сохраняются на повторах. При сетевой ошибке, ошибке шлюза или повреждённой квитанции результат записи uncertain: запись остаётся в устойчивой очереди. Подтверждённый бизнес-отказ обрабатывается отдельно. Автоматического fallback и записи в Firebase нет.

subscribeLine последовательно читает сессию и доступную линию; следующие циклы не перекрываются. onSession обязан немедленно обновлять доступ и очищать видимую линию, когда профиль disabled/deleted/pending, identityReady=false или tab_line отсутствует. onError должен показывать состояние соединения; нельзя подменять недоступную линию пустой успешной. Обработчики пользовательского интерфейса должны быть синхронными и не выбрасывать исключения. Отписка подавляет запоздалые callbacks; stop также прерывает HTTP-запросы.

Дальнейшая интеграция: заменить прямые Firestore-подписки выбранного NAS-режима, подключить отдельную устойчивую очередь и optimistic projection; перенести административные формы, справочники, смены, табель, игровые операции и присутствие. Переключатель Synology остаётся недоступным до полного подключения. Эталон Сводки/Архива не меняется: клиент сохраняет поля и порядок серверных данных, сортировку выполняет существующий renderer.

Локально 80 pass, 0 fail, 11 PostgreSQL-групп skipped; полный CI-результат проверяется отдельно. Браузерное подключение основных экранов и live Firebase JWT этими тестами не подтверждаются.
