# Следующий этап TEST: серверное сохранение Табеля 2

Статус: обновлённый API-кандидат запущен на NAS, готовность PostgreSQL подтверждена; 47 записей табеля перенесены и сверены с исходным импортом. Основной клиент TEST ещё не переключён.

## Реализовано

- Защищённый Firebase Auth API `GET/POST /api/v1/tabel/records` с PostgreSQL.
- Действующий статус пользователя, доступ к вкладке, право редактирования и права на лист проверяются сервером. Наблюдатель без права редактирования не может записывать.
- Администратор и старший прораб видят все листы; право записи старшего прораба определяется `timesheet_edit`. Остальным доступны листы по ACL пользователя/роли, дни доступны через разрешение linked. Изменение прав, переименование и удаление существующего листа доступны менеджерам.
- Ревизии, история и квитанции операций сохраняются атомарно. Изменённое тело с прежним ID отклоняется. Проверка повтора заново проверяет доступ.
- При несовпадении ревизии используется та же функция объединения, что в действующем клиенте; сервер сверяет базовую версию с собственной историей/исходной копией. Разные числовые значения одной ячейки требуют разрешения конфликта.
- Отдельный адаптер `test-app/synology/tabel-remote.mjs` совместим с существующим Store. Существующая IndexedDB-очередь остаётся владельцем повторов. Нет автоматической записи в другой источник при ошибке NAS.
- Пагинация чтения/истории и опрос изменений. Это не WebSocket; присутствие и цветные выделения ещё не перенесены.
- SQL `002_tabel.sql` добавляет таблицы без изменения исходного импорта. `seedTabel` требует точный SHA исходной тестовой копии и пустые целевые таблицы; сохранённая исходная запись используется для проверки последующих конфликтов. Повторное заполнение рабочего табеля запрещено.

## Границы

Этап не подключён к основным экранам. Операции закрытия смены/переноса материала, общий документный API, присутствие, права и профили из интерфейса, резервирование, переключение и общий офлайн-регресс ещё требуют реализации и проверки. Поэтому эта ветка не означает готовности TEST 4.0.

Перед установкой на NAS нужна свежая резервная копия PostgreSQL и исходников, проверка SQL в отдельной базе, затем установка нового образа и проверка HTTPS с Firebase-входом. Нельзя применять миграцию к production или перезаписывать импортированную базу. Фото удалены из приложения и в перенос не входят.
