# Индикатор сервера и проверка соединения TEST

Этап подготовлен поверх bde601949a47158325079315f6eb08cdf108d395. Основной клиент пока читает и записывает Firebase. Автоматическая репликация и переключение ещё не реализованы.

В кандидат TEST добавлен круглый индикатор источника данных: F — Firebase, S — Synology, О — работа локально. Во время начальной загрузки используется многоточие. Источник берётся из адаптера бизнес-данных; Firebase Auth и успешная проверка NAS не превращают индикатор в S. Нажатие открывает существующую диагностику синхронизации.

Администратор видит раздел «Сервер данных» с тремя режимами. Firebase остаётся единственным доступным режимом этой сборки. Synology заблокирован до подключения всех экранов, автоматический режим — дополнительно до проверки резерва. Выбор не сохраняется как будто он уже переключил адаптер, существующие локальные очереди не перемещаются. Это подготовка интерфейса, не реализация трёх работающих режимов.

Кнопка проверки делает только авторизованные GET линии и табеля через текущий внешний HTTPS-адрес. Проверяются формат, workspace, ревизия, ошибки доступа, однократное обновление токена, смена сеанса и таймаут. Успех старого API линии при 404 нового табеля не считается готовностью. В итогах показываются только счётчики; ГАИ исключён из обычного объёма. Токены не сохраняются и не выводятся.

Добавлены 10 сценариев состояния/транспорта и проверка связи HTML с manifest/service worker. Новые модули включены в офлайн-кэш и входы штатного сборщика. Изменений production, Firebase Rules, фото, данных и настроек NAS в этом этапе нет.

При проверке доступной сессии DSM вновь показал «Вы не можете войти в систему. Повторите вход». Внешний маршрут нового API не менялся. После восстановления сессии требуется направить существующий тестовый HTTPS-маршрут на проверенный API-кандидат и проверить авторизованный цикл. Основной TEST нельзя переключать до переноса оставшихся операций и проверки очередей.
