# Тестовая версия: модули и офлайн-PWA

Основа: `index-test.html` из коммита `a135b2c6f6316c446c1252f9fb65644099790490` (3.1.16). Результат: тестовая 3.1.17. Производственные `index.html`, манифест, Firebase-проект и правила не изменяются.

## Результат анализа

Исходная страница занимала 994 999 байт. В ней находились 29 собственных блоков JavaScript, 13 блоков CSS и пять подключений CDN. Основной блок JavaScript содержал общие переменные, авторизацию, подписки Firestore, очередь и пользовательские функции. Ещё 13 встроенных функций запускались через строки `eval` внутри одного блока. Табель, камера, фотографии, игровой режим и магазин уже имели границы, но хранились внутри HTML.

Главная сложность — взаимные зависимости: глобальные функции вызываются из HTML-обработчиков, плагины заменяют их через `window`, расширения оборачивают предыдущие реализации. Простое добавление `type="module"`, `async` или произвольное изменение порядка нарушило бы доступ к функциям, область видимости и момент регистрации обработчиков.

Размер HTML сам по себе не доказывает медленную синхронизацию. Очередь, транзакции, число подписок, тяжёлые перерисовки и уведомления требуют отдельных измерений. Их алгоритмы в этой работе не переписаны. Оценка задержек остаётся в [optimization-review.md](optimization-review.md).

Исходники разделены по функциям. Части ядра собираются в один скрипт с прежним порядком объявлений и общей областью видимости. Это совместимый промежуточный этап, **не полная изоляция через ES Modules**. Самостоятельные блоки подключаются внешними скриптами на прежних местах. Встроенные строковые патчи переведены в читаемый код с прежними границами обработки ошибок. Поддержка пользовательских динамических патчей сохранена.

HTML уменьшен примерно до 59 КБ; полный комплект для автономного запуска занимает около 3 МБ, включая библиотеки и шрифты. Функции не удалены ради уменьшения числа байтов. Отдельные файлы кэшируются, исходники читаются и проверяются независимо. Встроенное скачивание HTML по-прежнему собирает один файл, включая скрипты, стили и шрифт.

## Как работает офлайн

1. Открыть тестовую страницу по HTTPS с интернетом и дождаться сохранения файлов. Для установки использовать шестерёнку → «Приложение на телефоне» либо меню браузера.
2. Войти в аккаунт и загрузить нужную смену. Firebase сохраняет сессию и данные в браузере; раздел настроек отдельно показывает готовность файлов и постоянного хранилища.
3. Без сети страница открывается из Service Worker, в том числе после закрытия браузера. Существующая очередь сохраняет прибытие, погрузку, ТТН и поддерживаемые ею действия до отправки. Табель и локальные фотографии сохраняют свои существующие хранилища.
4. При возвращении сети в открытом приложении очередь обрабатывается прежними транзакциями: учитываются смена, версия, интервал и повтор. Если приложение закрыто, отправка продолжается при следующем запуске. Фоновая отправка при полностью закрытом приложении не обещается.
5. Первый вход в новый аккаунт, загрузка ранее не открытых данных и операции с обязательным серверным подтверждением требуют сети. Мини-игры не получают отдельного автономного денежного баланса. Кэш страницы не заменяет проверку прав и правила Firestore.

Без первого успешного онлайн-входа и загрузки смены готовность файлов не означает готовность рабочих данных. Если браузер запрещает постоянное хранилище, это явно показано. Удаление данных сайта пользователем или очистка браузером может удалить автономные данные; обновление приложения их не очищает.

## Изоляция и обновления

- Адрес и `scope` PWA: `./index-test.html`. Рабочая страница не контролируется тестовым Service Worker.
- Только точный список файлов приложения попадает в Cache Storage. Firebase/Auth/Storage, MAX, чужие страницы и запросы записи не кэшируются Service Worker.
- Файлы версии имеют путь с хешем. Каждое скачивание проверяется SHA-256; неполный или смешанный комплект не активируется.
- Новая версия ждёт закрытия всех окон тестовой программы. Нет `skipWaiting`, автоматической перезагрузки, удаления IndexedDB, localStorage или очереди.
- При активации удаляются только старые кэши с префиксом `samosval-test-shell-`. Производственные кэши и данные пользователей не затрагиваются.
- Публиковать HTML, Service Worker, манифест и новые файлы **одним коммитом**. Сохранить предыдущие опубликованные каталоги `build`, пока ими могут пользоваться открытые страницы.

## Как расширять дальше

Редактировать соответствующий файл в `src`, затем выполнить из корня:

```sh
python3 tools/build-test.py
node tests/pwa/modules.cjs
node tests/pwa/service-worker.cjs
node tests/pwa/run-regressions.cjs
```

Не запускать прежние `tests/*/build.cjs` для перезаписи HTML: их функция сборки заменена общей командой. Старые `assets/*` сохранены ради других версий и инструментов; они больше не являются источником тестовой страницы. Для старых тестов, читающих inline-код, есть `tools/read-test-html.cjs` и `tests/pwa/legacy-loader.cjs`.

Следующий отдельный этап, если потребуется: явные интерфейсы хранилища/авторизации/событий вместо глобальных переменных; затем постепенная изоляция модулей и измерения производительности. Не следует одновременно с этим переписывать алгоритм рейсов или делать новый общий офлайн-режим: сначала нужны сценарии совместимости и проверки двух устройств.

## Проверки

`tests/pwa/modules.cjs` сравнивает перенесённый код с исходным коммитом: алгоритмы ядра и самостоятельные блоки сохранены; разрешены только явно описанные подключения PWA, уведомление о постоянном хранилище и адаптация экспорта. Проверяет синтаксис и хеши файлов.

`tests/pwa/service-worker.cjs` проверяет автономную выдачу всех файлов, изоляцию рабочей страницы/API, отказ при незавершённом обновлении и очистку только собственного кэша.

`tests/modular/` проверяет ТТН, независимые версии карточек, ограничения смены, покупки/ставки, 25 тем, эффекты, анекдоты и разделение рейтинга и кошелька.

`tests/pwa/browser.cjs` запускает настоящий Chromium, настоящий Firebase SDK и IndexedDB с локальным Firestore Emulator. Личность пользователя задаётся тестовой фикстурой; в действующую базу тест не обращается. Проверяет установочный манифест, запуск без сети после полного закрытия браузера, сохранение очереди и отправку ровно одного рейса при возвращении сети. Настоящий Android, системный диалог установки и восстановление реального Firebase Auth остаются отдельной проверкой на телефоне владельца.

### Фактический результат проверки 25 октября 2026

- 38 перенесённых блоков совпали с исходными побайтно. Ядро после исключения двух подключений PWA совпало с исходным кодом. Все 13 встроенных расширений сохранили исполняемый код и обработку ошибок; у экспорта добавлено встраивание внешних файлов.
- Компиляция 35 выполняемых скриптов и проверка хешей всех 55 файлов автономной версии прошли.
- Проверки очереди/ТТН, смены, кошелька, тем, эффектов и таймера анекдотов прошли.
- Chromium 156 подтвердил пригодность манифеста к установке и готовность постоянного хранилища Firebase. После полного закрытия браузера без сети восстановились права, смена и три отложенных действия. После возврата сети локальный Firestore под действующими правилами принял их, создав один рейс; повтор не создал второй.
- Однофайловый экспорт без сети включил все скрипты, стили и шрифт; его скрипты проверены компилятором.
- Новая версия Service Worker ожидала закрытия страницы; после активации и повторного автономного запуска отложенное действие и локальные данные сохранились.
- Тестовая личность в браузере — фикстура. Вход настоящего пользователя, системная установка на Android и действующая облачная база в этой проверке не использовались.
