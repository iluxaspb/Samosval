# Новый «Табель» — 2.0.0-test.1

Самостоятельное **второе** тестовое расширение `builtin-tabel-next`. Написано отдельно по ТЗ и уточнениям владельца. Существующее расширение `builtin-tabel`, его файлы и данные не изменены. Базовый commit: `5bc6325c7344fb543d3388fd7c27fe459ede81dd`.

## Статус

Реализация подготовлена в отдельной ветке/PR, **не опубликована на действующем сайте**. По умолчанию работает локально с сохраняемой очередью: отправка данных в новые Firebase-коллекции отключена до согласования и применения правил. Это намеренное ограничение безопасности: действующий общий wildcard допускает доступ к неизвестным коллекциям и без отдельного исключения обходит объектную ACL.

Серверный адаптер и оба проекта правил проверены настоящим Firebase SDK в Firestore Emulator. Это не подтверждение работающей синхронизации на сервере. Результаты: [results.json](../../tests/tabel-next/results.json), [приёмка](ACCEPTANCE.md).

## Согласованные изменения модели

- Своя техника: часы агрегата + отдельные **обезличенные суммарные** часы персонала. `52` сохраняется как `52`, не делится между людьми. Для персонала нет ограничения 24 часа; часы одного агрегата/помпы/конкретного работника ограничены 24.
- Фреза + машинисты фрезы; трактор + тракторист; поливомойка + водитель, помпа — необязательная третья строка с отдельными часами.
- Наёмная техника — одна строка часов, без персонала. Пофамильно учитываются только ИТР и рабочие.
- Таблица и смена редактируют **одну запись смены**. Дневная и ночная смены раздельны, ночь относится к дате начала. Из таблицы можно добавить прошлый/текущий/будущий день. Будущий день — только плановый состав, без факта.
- Заявка выбирает технику из собственной общей базы нового расширения. Недостающую технику/человека можно добавить там же. Шаблон состава для новых объектов сохраняется отдельно. Новый объект создаётся в общей базе объектов приложения и доступен «Линии»; действующая смена «Линии» автоматически не переназначается.

## Экраны и редактор

Все разделы размещаются полноэкранно поверх оболочки. Таблица использует компактную панель, строку формул, буквенные столбцы и номера строк, нижнюю полосу листов. Первый лист сохраняет секции и цвета эталона; левый столбец и даты закреплены. Весь период от начала объекта, фильтр понедельник–воскресенье; незаведённые календарные дни не создают записей до ввода/явного добавления.

Любой лист: размеры строк/столбцов (перетягивание и точные значения), фон/цвет текста, шрифт, жирный/курсив, выравнивание, перенос, границы, числовой формат. Диапазон можно указать в адресном поле, выбрать заголовком строки/столбца. Контекстное меню открывается длительным нажатием. Копирование/вставка, очистка с сохранением оформления, отдельно очистка всего, автозаполнение маркером/меню, отмена/повтор. Связанный лист выполняет операции через записи смен, не подменяет вычисления копией таблицы.

Свободные листы: безопасные ссылки, `+ - * /`, скобки, `SUM` / `СУММ`, десятичная запятая; ошибки ссылок/цикла/деления на ноль. Формулы не исполняют JS. Максимум 1000 × 100, частичный показ по 80 строк с переходом на 60; предел записи 700 КБ. На первом листе формулы вместо фактических часов не принимаются — это числовые первичные данные. Дополнительный лист-шаблон не связан с учётом.

Панель символов использует VisualViewport и сохраняет фокус ввода. На физическом Android не проверена. Для гарантированного применения значения служит `✓`/Enter, незавершённый ввод сохраняется в локальном черновике.

Заявка, обед и отчёт используют редактируемый предпросмотр, системное Web Share и копирование. Доставка сообщений приложением не подтверждается. Обед всегда на завтра. В отчёте используются факт смены и отдельный read-only источник прибытий «Линии»; неполная история помечается.

## Хранение и границы

- IndexedDB: `samosval_tabel_next_v1_<project>_<workspace>_<uid>`. Старые IndexedDB/очереди не читаются и не меняются.
- Отдельные серверные коллекции (после разрешённого подключения): `tabelNextRecords`, `tabelNextOperations`.
- Записи конфигурации, смен и листов разделены по объекту; база и шаблон имеют `_catalog` / `_defaults`. В локальном режиме общая база/шаблон доступны только на этом устройстве и аккаунте; после серверного подключения — в рабочей области.
- Каждая операция содержит ожидаемую ревизию. Подтверждение своей предыдущей записи не создаёт ложный конфликт. При настоящем конфликте сохраняются старое/текущее/предложенное значения; явное решение фиксируется в истории. Несколько правок разных дней — отдельные операции, не одна серверная транзакция на весь диапазон.
- Локальные изменения и очередь записываются атомарно; Web Locks/BroadcastChannel координируют вкладки. Отозванное право не обходится очередью. Автоподписка охватывает окрестность выбранного дня (31 день назад / 7 вперёд); ручная синхронизация перечитывает загруженные записи.
- Изменения ядра: только узкий `ledgerHost.createObject(name,startDate)`, проверяющий существующее `manage_objects`, и подключение второго загрузчика. Данные рейсов/TTN, бизнес-логика «Линии», production, текущие Firebase Rules и старый табель побайтно проверены.

## Запуск и проверки

```sh
npm ci --prefix tests/tabel-next --ignore-scripts --no-audit --no-fund
python3 tools/build-test.py
node tests/tabel-next/run.cjs
# При наличии браузера и Java/Firestore Emulator:
TABEL_BROWSER_EXECUTABLE=/path/to/chromium \
FIRESTORE_EMULATOR_JAR=/path/to/cloud-firestore-emulator-v1.19.8.jar \
node tests/tabel-next/run.cjs --browser --emulator
python3 -m http.server 8765 --bind 127.0.0.1
```

`http://127.0.0.1:8765/index-test.html` — тестовая оболочка с авторизацией и вторым расширением. `http://127.0.0.1:8765/tests/tabel-next/harness.html` — синтетическая локальная проверка без реального Firebase; `?local=1` проверяет выключенную синхронизацию.

## Серверное подключение — отдельная неисполненная часть

[Минимальный diff](proposals/firebase-integration.patch) подготовлен **относительно репозиторного** `firestore-timesheet-test.rules`, а не неизвестного актуального live ruleset. Он исключает две новые коллекции из общего wildcard и добавляет только их правила. [Интегрированный кандидат](proposals/firestore.integrated.rules) не заменял действующие правила.

Перед применением: отдельное разрешение владельца, сохранение актуального live baseline, перенос этих же двух ограниченных изменений на него и повтор эмуляторных тестов. После серверной проверки изменить только вызов нового загрузчика на `m.mount(ctx, container, {remoteEnabled:true})`, пересобрать тестовую PWA и проверить два реальных устройства. Не включать флаг только ради исчезновения предупреждения.

Отдельно остаётся точное соответствие дневной/ночной смены табеля ID смен «Линии»: основной источник не предоставляет достоверного такого признака. Поэтому для отдельной смены число самосвалов не выдаётся за подтверждённое; общий отчёт за день использует прибытия с видимым предупреждением при неполноте. Автоперенос кубометров в материалы выключен.
