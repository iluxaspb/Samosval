# Новый встроенный Табель — рабочая ветка

Статус: встроенный тестовый экран и локальные черновики, **не готовое приложение и не опубликованный выпуск**.
Последнее согласованное задание: [PLAN-2026-10-28.txt](PLAN-2026-10-28.txt).
Baseline: `5bc6325`. Старый `test-app/tabel` не изменяется и не используется
как основа нового UI/хранилища.

## Реализовано в этой ветке

- Новые смены с сохранением настроек и пустым фактом; дневная/ночная идентичность.
- Строки своей/наёмной техники, опциональная помпа, обезличенные часы без
  распределения по людям и ограничения суммарной строки 24 часами.
- Раздельный план/факт работ; поиск и ранжирование справочников.
- Проверяемое предложение переноса закрытой смены: группировка м³ по материалу
  и направлению, версии, повтор без удвоения, удалённые направления, ручные
  конфликты с сохранением обоих вариантов. Функция не выполняет запись сама.
- Подсчёт уникальной техники, включая уехавшие самосвалы без погрузки,
  объединение ID/госномера, исключение ГАИ/помпы/строк экипажей.
- Каталог прав и чистая проверка ролевых/персональных прав и области объекта.
  Это НЕ серверная защита и пока НЕ подключённая админка.

Проверка: `node --test tests/tabel-v2/*.test.mjs`.

## Обнаруженный контракт Линии

`test-app/source/core/15-shifts.js` при закрытии читает серверные logs/status,
формирует архив и очищает исходные записи. Архив явно копирует ограниченный
список полей: материала и назначения рейса среди них нет. Архив создаётся
только при наличии рейсов. Самосвал без погрузки, который уже уехал, нельзя
надёжно восстановить из одного текущего счётчика `onLine`.

До подключения автопереноса необходимо:

1. Хранить стабильные object/shift/material/destination ID у рейса, а не
   определять материал старого рейса по текущим настройкам. Для исторических
   рейсов без этих данных запросить явное сопоставление, не гадать.
2. Сохранять полный снимок закрытой смены и журнал прибытия даже без рейсов.
   Указать дату начала и вид смены; `sourceShiftId`, монотонную revision,
   полноту снимка и направления. Привязку к дате не выводить из времени закрытия.
3. Перед очисткой первичных данных надёжно сохранить источник для повторного
   переноса; не делать зависимость от того, открыт ли экран табеля.
4. Добавить отдельную очередь и атомарную серверную запись с проверкой прав,
   ревизии цели, квитанцией операции и сохранением конфликта. Чистый domain
   не решает конкуренцию клиентов и не подтверждает доставку.
5. Подключить ленивый встроенный экран, шестерёнку с шестью модальными окнами
   и каталог прав к существующей админке. Проверить отзыв прав при синхронизации.

Действующее закрытие использует серверную транзакцию и требует синхронизировать
действия до закрытия. Полноценное закрытие офлайн ещё не реализовано: утверждённое
требование очереди нельзя объявлять выполненным без отдельной интеграции.

## Осталось до готовности

Полноэкранные UI и редактор, справочники/объекты и настройки, заявки/шаринг,
долговечное хранилище и очередь, серверная защита, интеграция с Линией и админкой,
двухпользовательские/офлайн/браузерные проверки, сборка тестовой PWA.
Никаких изменений core, production, старого табеля или Firebase Rules этот
этап не вносит. Файлы не включены в runtime/PWA manifest, поэтому текущая
программа не загружает эту незавершённую реализацию.

Откат этого этапа: удалить добавленные `test-app/tabel-v2` и `tests/tabel-v2`
в своей рабочей ветке либо revert соответствующего коммита. Пользовательские
данные и базы этот этап не изменяет.


## Встроенный экран — 28 октября

Кнопка «Табель 2» в тестовой навигации и шестерёнка рядом с объектом открывают
лениво загружаемый модуль напрямую, без менеджера расширений. Объект берётся
из активной смены, люди и техника читаются из существующих справочников.
Пустая база не заменяется демонстрационными записями. Ошибка чтения блокирует
открытие, а не создаёт видимость успешно загруженного пустого списка.

Есть шесть модальных окон, поиск с сохранением выбранных позиций, выбор даты
и дня/ночи внутри ввода факта, общий план и остаток. Данные нового табеля
сохраняются ТОЛЬКО как localStorage-черновик по проекту/пространству/пользователю/
объекту. Это не серверное сохранение, не резервная копия и не офлайн-очередь.
Очистка браузера удалит черновик; одновременное редактирование из нескольких
вкладок пока не поддерживается. Вход в модуль требует текущего права timesheet,
сохранение черновика — timesheet_edit. Проверка повторяется перед записью;
при смене пользователя/объекта или отзыве просмотра окно закрывается.
Гранулярные права, серверные транзакции, история и конфликты ещё не подключены.

Проверки: 18 domain-тестов; browser-smoke.cjs с подставным host (не реальная
Firebase-сессия): мобильный размер 393×852, поиск и выбор, план/факт,
запись прошлой ночной смены, повторное открытие черновика, новая смена,
отзыв доступа. Для запуска: HTTP-сервер репозитория на 8765 и
`PLAYWRIGHT_PACKAGE=/path/to/playwright CHROMIUM_PATH=/path/to/chrome node tests/tabel-v2/browser-smoke.cjs`.
На физическом Android и в опубликованной тестовой PWA не проверено.
Старый verify-test-modules.py падает на числе блоков исходного baseline
ещё до проверки новых файлов; этот сбой не объявляется успешной проверкой.
