# Границы интеграции и оставшаяся серверная часть

Владелец отдельно разрешил необходимые изменения основного тестового файла для подключения через «Админка → Расширения» и удаления старого табеля. Этим разрешением покрыты тестовая оболочка, блок менеджера, сборщик, тестовая PWA и метаданные выпуска. Production, общие Firebase rules и логика «Линии» разрешением не затронуты.

## Выполненная тестовая интеграция

`source/shell.html` удаляет прежний контейнер/кнопку табеля и подключения старого runtime/CSS; добавляет реестр плагина. Из `source/core/04-subscriptions.js` меняется только блок плагинов между маркерами ПЛАГИНЫ и АВТОРИЗАЦИЯ. Добавлены lifecycle, поставляемый код, настройки и ограниченный табельный API. Проверка `tools/verify-test-modules.py` сравнивает всё за пределами этого блока с прежним кодом.

Сборщик включает runtime плагина в cache manifest и штатно создаёт `index-test.html`, `sw-test.js`, `build-manifest.json`, новый `build/<hash>/`. Исходный механизм установки/активации worker сохранён. Риск — обновление открытого клиента; проверены повреждённый пакет, офлайн и фактическая активация worker на локальном предыдущем выпуске.

## НЕ применено: Firebase

Защищённый файл `firestore-timesheet-test.rules` не изменён. Опубликованные правила не считывались и не развёртывались: у сессии нет доступа администратора Firebase. Проект минимального diff: [firebase-integration-NOT-APPLIED.patch](proposals/firebase-integration-NOT-APPLIED.patch). Полный кандидат только для эмулятора: [firestore.integrated-emulator.rules](proposals/firestore.integrated-emulator.rules).

Кандидат добавляет четыре коллекции в строгую валидацию квитанций, исключает их из широкого fallback, проверяет активный аккаунт, главное право табеля, объектную ACL и revision. Старые объекты без настроек сохраняют прежнюю политику записей смены/материалов. Правила «Линии», рейсов, монет и пользователей не меняются.

Риск: реальные правила могут отличаться от репозитория; Firestore объединяет разрешения через OR, поэтому одного нового разрешающего match недостаточно. Перед отдельным развёртыванием требуется сравнить опубликованные тестовые rules и согласовать конкретный diff. `firestore.sandbox.rules` запрещает основное приложение и не предназначен для публикации целиком.

Успех эмулятора не доказывает работу реальной Firebase. Пока правила не интегрированы, операции новых коллекций могут получать серверный отказ и сохраняться в локальной очереди. Остальная тестовая публикация от этой части не зависит.

## Неизменённые участки

`index.html`, production app/worker/manifest, `.github/**`, общие rules, логика рейсов, кнопок, очереди и синхронизации «Линии» сохранены. Guard сравнивает 834 защищённых исходных файлов с baseline `8b0bd65`. Настройки защиты веток, CODEOWNERS и права GitHub не менялись.

## Уточнение проверки обновления

Локальный HTTP-fixture `tests/pwa/update-browser.py` дополнен путём `test-app/tabel/` и переписыванием тестового projectId для JS/ES modules этого каталога. Прежний список возвращал 404 новым precache-ресурсам. CSP, sandbox Chromium, запрет внешней сети и все assertions сохранены. Сборочный hash теперь учитывает только runtime HTML/JS/CSS, а не README, чтобы правка документации не меняла пакет.
