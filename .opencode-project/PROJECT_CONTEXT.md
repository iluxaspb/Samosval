# КОНТЕКСТ ПРОЕКТА «УЧЁТ САМОСВАЛОВ» И ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА

## 1. Жёсткое правило делегирования (требование владельца)
- **Главный агент не делает работу руками сам.** Его обязанность — руководить процессом, ставить задачи подчинённым агентам, держать статус и отвечать владельцу.
- **Все задачи распределяются подчинённым агентам:**
  - `samosval-coder` — программный код, модули, исправления, сборка бандлов;
  - `samosval-tester` — тестирование через Playwright MCP, регрессионные тесты, скриншоты, проверка ролей;
  - `samosval-architect` — архитектурный анализ, аудит безопасности, проверка оффлайн-синхронизации и БД.
- **Модель для подчинённых агентов:** строго экономичная и качественная модель `apimira/google/gemini-3.8-flash`.
- Главный держится свободным для владельца: он планирует, распределяет задачи, проверяет результаты и отчитывается по-русски, кратко и по делу.

## 2. Изоляция рабочих сред и безопасность данных
- Основная боевая версия (`index.html`) и продуктивная база данных (Firebase / PostgreSQL / NAS) **неприкосновенны** без отдельного прямого указания.
- Вся тестовая разработка ведётся строго в `index-test.html` и в каталоге `test-app/`.
- Сборка тестовой версии выполняется исключительно скриптом `python3 tools/build-test.py`, который генерирует согласованный `index-test.html`, `sw-test.js` и `build-manifest.json`.

## 3. Регламент выпуска тестовых релизов (TEST PWA)
- Каждому выпуску присваивается актуальная версия в:
  - `test-app/source/shell.html` (`meta[name="test-app-version"]` и номер в шапке);
  - `test-app/source/features/test-release.js`;
  - `test-app/source/features/release-history.js` (понятное описание изменений для прораба и администратора).
- Перед публикацией обязательно прогоняются проверки Playwright MCP.
- После успешных тестов изменения коммитятся в feature-ветку и публикуются на GitHub.
