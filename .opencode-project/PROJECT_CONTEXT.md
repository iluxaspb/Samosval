# Проект «Учёт самосвалов» — контекст разработки

## Назначение
Многопользовательская веб-система учёта самосвалов,
рейсов, работников, техники, материалов и рабочих смен.

Репозиторий: iluxaspb/Samosval
Frontend: GitHub Pages.
Основная страница: index.html.
Тестовая страница: index-test.html.

Актуальную структуру и версии обязательно проверять
по фактическому содержимому репозитория.

## Основная архитектура
- Основной сервер: Synology DS923+, API и PostgreSQL.
- Firebase: авторизация и резервное хранение данных.
- При отказе основного сервера предполагается
  автоматическое переключение клиентов на резерв.
- После восстановления требуется согласованное
  возвращение к основному серверу.
- Репликация, разрешение конфликтов и восстановление
  должны быть безопасными и проверяемыми.
- GitHub Pages содержит интерфейс, а не основную БД.

Внимание: перечисленные механизмы являются
проектными требованиями. Реализацию и готовность
проверять по коду, не считать автоматически завершёнными.

## Линия
- Перед первым рейсом обязательна отметка
  «Приехал на линию».
- После ухода с линии требуется новое прибытие.
- Существует общий минимальный интервал между погрузками.
- При одновременной погрузке несколькими операторами
  событие должно учитываться только один раз.
- Offline-first: действия не должны пропадать при
  отсутствии сети, необходима очередь синхронизации.
- Все отмены и восстановления подлежат аудиту.
- Статусы и анимации должны оставаться согласованными.

## Сводка — эталон
- Самосвалы сортируются сверху вниз по времени
  ПЕРВОЙ погрузки в смене, от ранней к поздней.
- Самосвалы без рейсов всегда внизу.
- Рейсы внутри строки идут слева направо по времени.
- Подпись строки: объём м³ / количество рейсов.
- При открытии всегда обычный белый лист, не режим ГАИ.
- Не нарушать масштабирование, панорамирование
  и визуальную геометрию белого листа.
- Эталонную сортировку не менять без разрешения.

## Табель и техника
- Категории: ИТР, рабочие, машинисты/водители, техника.
- По умолчанию фреза: два машиниста.
- МТЗ-щётка: один тракторист.
- Часы фрезы и машинистов учитывать отдельно.
- Материалы привязаны к объектам и сменам.
- Сохранять фокус на редактируемой карточке.
- Состав смены и адрес должны быть согласованными.
- Счётчик техники: уникальные самосвалы на линии
  за текущий день без ГАИ плюс техника в табеле.
- Выходные дни отмечаются отдельно.
- Табличные формулы, импорт/экспорт Excel и PDF,
  совместное редактирование — проектные требования.
- Не считать незавершённую функцию уже работающей.

## Другие модули
- Архив смен и объектов.
- Журнал аудита, отмена/восстановление событий.
- Аналитика рейсов и рабочего времени.
- Регистрация пользователей и роли доступа.
- Несколько объектов одновременно.
- Игровой режим, монеты, рейтинги и мини-игры.

## Права доступа
Роли включают администратора, лопатёра, ГАИ,
ИТР, рабочих, наблюдателя и старшего прораба.
Фактическую матрицу разрешений проверять по коду.
Не расширять доступ без согласования.

## Инфраструктура
- Рабочую инфраструктуру Synology не менять
  при обычных задачах интерфейса.
- PostgreSQL и Firebase не сбрасывать.
- Не стирать журналы, архивы или пользовательские данные.
- Не изменять серверную схему без миграции,
  резервной копии и отдельного согласования.
- Избегать расхождения данных между S и F.

## Стандарты разработки
- Действовать точечно, не переписывать всё приложение.
- Сохранять мобильную адаптацию.
- Учитывать работу 2–4 операторов одновременно.
- Любое изменение сопровождать тестами.
- Сначала изучить существующие тесты и структуру.
- Проверять побочные эффекты в других разделах.
- Записывать версию и краткий список изменений.
